# 枠に収まらないターミナルを自動で拡大するのをやめる

- 日付: 2026-10-22
- ストーリー: #126

## 背景

#68（docs/adr/68-zoom.md）で、分割した画面でフォーカスしているターミナルが自分の枠に収まらないとき、自分の画面だけでそのターミナルを自動で拡大するようにした。当時は、端末の大きさを参加者のうち一番大きい表示領域に合わせていた（docs/adr/51-largest-size.md）ので、画面の小さい参加者はたびたび枠に収まらなかった。

その後、端末の大きさは一番小さい参加者に合わせ、下限まで広げる形になった（#99、docs/adr/99-smallest-size.md）。枠に収まらないのは、分割した枠が下限より小さい人がいて、ほかの参加者の枠のほうが広いときなどに限られる。そうした場面で、フォーカスしたターミナルが勝手に画面いっぱいに広がり、ほかのターミナルが見えなくなるほうが分かりにくい。

## 決定

- 自動の拡大をなくす。分割した画面では、フォーカスしているターミナルが枠に収まらなくても、分割したまま表示する。はみ出した部分は、これまでどおりスクロールか縮小（表示の設定「画面に収める（縮小）」、docs/adr/36-appearance.md）で見る
- 拡大を外す・戻す操作もなくす。ショートカット（⌘⇧Z / Ctrl+Shift+Z）、ペインのバーのボタン（⤢）、右クリックメニューの「拡大表示」／「拡大を解除」、バーの「拡大中」「拡大を外しています」の表示、ショートカットの一覧の「拡大表示の切り替え」
- ⌘⇧Z / Ctrl+Shift+Z は、ほかの割り当てのない Ctrl+Shift+文字と同じ扱いに戻す。ページでは何もせず、シェルにも何も送らない（xterm は Ctrl+Shift+文字をブラウザに任せ、⌘ の付いたキーは送らない）
- 端末の大きさは、ペインの表示領域（`.pane-terminal`）だけから計算する。拡大中に元の分割の枠の大きさを測るための仕組み（元の位置に置く要素、`splitArea`、枠に収まるかの判定 `overflows`、収まるかが変わったことの通知）はなくす
- フォーカスの移動（隣のターミナルへ、ペアプロモードの追従）は、拡大を決め直さずにそのまま移る

## 理由

- 一番小さい参加者に合わせるようになり、はみ出す場面が限られた。限られた場面のために、画面の見え方が勝手に変わる仕組みを残すより、分割したまま見せて、スクロールか縮小で見るほうが分かりやすい
- 拡大を外す・戻す操作は、自動の拡大を前提にしたもので、自動の拡大がなければ意味がない（枠に収まっているターミナルでは、もともと選べなかった）
- 1 つのターミナルを画面いっぱいに見る方法は、#100（ターミナル 1 つ = タブ 1 つにし、タブを 1 つ選べば画面いっぱいに出る）で用意する。tmux のズームのような、いつでも使える拡大をここで作り直さない
- Ctrl+Shift+Z をシェルに Ctrl+Z として送ることもできるが、Shift なしの Ctrl+Z が届くので必要がなく、ほかの Ctrl+Shift+文字（割り当てのないもの）と扱いが揃っているほうが分かりやすい

## 影響

- 分割した枠が下限より小さい参加者は、フォーカスしているターミナルもスクロールか縮小で見ることになる
- macOS の Chrome では、⌘⇧Z はブラウザの「やり直す」に戻る（ターミナルの入力欄では何も起きない）
- docs/adr/68-zoom.md の決定は、この ADR で置き換える。docs/adr/99-smallest-size.md のうち「#68 の自動の拡大で見る」とした部分は、スクロールか縮小で見ることになる

## 含めないもの

- 1 つのターミナルを画面いっぱいに見る方法（#100 で扱う）
- 枠に収まらないことを知らせる表示
