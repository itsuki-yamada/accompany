# コマンドは、最初の参加者から端末の大きさが届いてから、その大きさで起動する

- 日付: 2026-10-29
- ストーリー: #208

## 背景

これまでは、ターミナルに最初のブラウザがつながった時点（`TerminalSession.attach`）で、コマンドを 80x24（再起動のあとは、保存した画面の大きさ）で起動していた。そのすぐあとにブラウザから大きさが届き、`fitToSmallest` で PTY を広げていた。

起動したコマンドから見ると、起動直後に大きさが変わり、SIGWINCH が届く。コマンドが SIGWINCH を受けられるようになる前に届くと、その通知は捨てられ、コマンドは起動時の大きさのまま表示し続ける。#205（PR #206）で、E2E の偽のコマンド（Bun の `process.stdout` は、大きさを読んでから SIGWINCH のハンドラーを付けるまでに間がある）がこれで落ちた。Claude Code などの本物のエージェントでも、理屈の上では起こりうる。

起動を大きさがわかるまで遅らせるにあたって、次のことを決める必要があった。

1. 大きさが届かないときにどうするか
2. 下限（`--min-window`）や、一番小さい参加者に合わせる計算（`fitToSmallest`）との関係
3. 保存した画面を戻すとき（再起動）、つなぎ直し、複数のペイン（分割・タブ）でどうなるか

## 検討した選択肢

### 大きさが届かないとき

1. 届くまで起動しない
2. 待つ上限を設け、上限までに届かなければ、それまでの大きさ（80x24、または保存した画面の大きさ）で起動する

### いつ起動するか

1. 最初に届いた大きさで、そのまま起動する
2. 届いた大きさを、ほかの参加者の分と合わせて `fitToSmallest` で決めてから起動する

## 決定

- コマンドは、参加者から大きさが届いたときに起動する。起動する大きさは、ふだんの大きさの変更と同じく、`fitToSmallest` で決めたもの（いまつながっている参加者のうち一番小さい表示領域を下限まで広げ、512 列・256 行までに切り詰めたもの）にする。参加者が 1 人なら、その人の表示領域の大きさになる
- 最初のブラウザがつながってから 2 秒（`sizeWaitMs`）待っても大きさが届かなければ、それまでの大きさで起動する
- 起動の契機が「つながったとき」から「大きさが届いたとき」に変わるだけで、ブラウザがつながる前には起動しない（起動直後の出力を取りこぼさない）点は変えない
- 閉じた（`kill`）あとは、大きさが届いても、待つ上限が来ても起動しない

## 理由

- 届くまで起動しないと、大きさを伝えないクライアント（改造したもの、測れないまま止まったものなど）しかいないとき、コマンドがいつまでも起動しない。これまでどおりの大きさで起動するほうが、起動しないよりよい。上限は、ふつうのブラウザではつないですぐ（WebSocket を開いたとき）に大きさを送るので、遅いネットワークやブラウザでも届く長さとして 2 秒にした
- 大きさを送る前に別の参加者がつながっていることもあるので、最初に届いた 1 人の大きさをそのまま使うのではなく、ふだんと同じ計算を通す。こうすると、下限・上限・一番小さい参加者に合わせる決まり（docs/adr/99-smallest-size.md、docs/adr/51-largest-size.md）が、起動するときにもそのまま効く
- 保存した画面を戻すときは、サーバー側の画面を保存した大きさで書いてから、届いた大きさに合わせて広げ直し、そのあとで起動する。コマンドは届いた大きさで起動する
- つなぎ直したときや 2 人目以降の参加者では、コマンドはもう動いているので、これまでどおり `fitToSmallest` で大きさを変える
- 分割や新しいタブのターミナルは、それぞれのペインがつながって大きさを送るので、ペインごとにその表示領域の大きさで起動する。表示していないタブのターミナルは、これまでどおり表示されて（つながって）から起動する

## 影響

- 最初の参加者の画面が 80x24 でないとき、コマンドは起動した時点からその大きさで動き、起動直後の大きさの変更（SIGWINCH）がなくなる
- ブラウザがつながってから起動するまでに、大きさが届くまでの時間（ふつうはすぐ）がかかる。大きさを伝えないクライアントしかいないときは 2 秒遅れる
- 起動したあとの大きさの変更（2 人目の参加者、ウィンドウの大きさの変更、1 文字の大きさの測り直しなど）は、これまでどおり SIGWINCH で伝わる。起動の直後にそれが起きると取りこぼされうることは変わらないので、E2E の偽のコマンド（`e2e/fixtures/corner-reporter.ts`、`size-reporter.ts`）が大きさを読み直す仕組み（docs/adr/205-parallel-e2e.md）は残す
- E2E では、起動した時点の大きさを一度だけ表示する偽のコマンド（`e2e/fixtures/start-size-reporter.ts`）で確かめる。読み直しも SIGWINCH も使わない。コマンドの起動の速さに左右されないよう、ブラウザが送る大きさを少し遅らせて届ける
