# 並べたタブの位置を入れ替え、分割の向きを変える

- 日付: 2026-10-23
- ストーリー: #163

## 背景

#100（docs/adr/100-terminal-tabs.md）で、タブを 3 つまで並べて見られるようになった。参加者ごとの表示は、サーバーが持つ分割の木（葉がタブ、節が向きと割合）で、本人と、ペアプロモードで追従している人にだけ配る。並べたあとに、タブの位置を入れ替えたり、左右の並びを上下に（またはその逆に）変えたりしたい。

迷ったのは、次の点。

1. 入れ替えの単位（2 つのタブか、分割の左右・上下か）
2. 3 つ並べているとき（入れ子の木）に、どの節の向きを変えるか。変えたあとの割合
3. 操作（ドラッグ・メニュー）と、タブの並べ替え（#139）のドラッグとの見分け
4. サーバーへの伝え方と検証、ペアプロモードとの関係

## 検討した選択肢

1. 入れ替えの単位
   - A. 2 つのタブ（葉）を入れ替える
   - B. 分割の節の 2 つの子（左右・上下）を入れ替える
   - C. A と B の両方
2. 向きを変える節
   - A. 一番外の節
   - B. 操作した場所の節（ターミナルなら、それを含む一番内側の節。境界なら、その境界の節）
3. タブの並べ替えとの見分け
   - A. ターミナルのバーをドラッグして、ほかのターミナルに重ねる（並べ替えはサイドメニュー・ツールバーのタブをドラッグする）
   - B. サイドメニューのタブを、ターミナルの上にドラッグする
4. 伝え方
   - A. 操作の結果の木を送る
   - B. 操作（入れ替える 2 つのタブ、または節の ID）を送り、サーバーが木を変える

## 決定

1 は C、2 は B、3 は A、4 は B を採る。

ショートカットは足さない。ショートカットは別の Issue で扱い、まずはマウスで操作できるようにする（利用者の方針）。

### 操作

- 2 つのタブの入れ替え: ターミナルのバーをドラッグして、ほかのターミナルに重ねて離すと、その 2 つの位置を入れ替える。重ねている間は、入れ替える先のターミナルに「ここと入れ替える」を重ねて出し、ドラッグしているターミナルは薄くする。節（向きと割合）はそのままで、葉だけが入れ替わる。バーの名前の入力欄を出している間は、バーをドラッグできない
- 分割の左右・上下の入れ替え: ターミナルの右クリックのメニューの「左右を入れ替える」「上下を入れ替える」は、そのターミナルを含む一番内側の、その向きの節の 2 つの子を入れ替える。子の大きさも一緒に動く（割合を 1 − 割合にする）。その向きの節がなければ選べない
  - 例: 1 が左、2 が右上、3 が右下のとき、2 で「上下を入れ替える」と 3 が右上、2 が右下になる。1（または 2・3）で「左右を入れ替える」と、右の 2 つが左に、1 が右になる
- 向きの変更: ターミナルの右クリックのメニューの「上下に並べる」（左右に並んでいるとき）・「左右に並べる」（上下に並んでいるとき）は、そのターミナルを含む一番内側の節の向きを変える
- これらの項目は、メニューの「右に分割」「下に分割」の前に出す。1 つだけ表示しているときは出さない。入れ替えるものも向きを変える分割もないので、出しても意味がない（選べない項目が並ぶだけになる）。並べる前のメニューがこれまでと同じ長さのままになり、狭い画面でメニューが右クリックした位置からずれることもない
- 境界の右クリック: 境界を右クリックすると、その境界の節について「左右を入れ替える」（上下の境界では「上下を入れ替える」）と「上下に並べる」（「左右に並べる」）を出す。3 つ並べているときに、外側の節を選ぶ方法になる。右クリックでは境界のドラッグを始めない。境界を右クリックできることは気づきにくいので、境界のツールチップに「ドラッグで大きさを変える。右クリックで入れ替え・向きの変更」と出す。ターミナルのバーのツールチップにも「ドラッグして別のターミナルに重ねると、位置を入れ替える」と出す（バーの名前やボタンの上では、それぞれのツールチップが出る）
- 向きを変えたら、割合は均等に戻す。同じ向きに並んだ 3 つは 3 等分、そうでなければ半分（`balance`。docs/adr/100-terminal-tabs.md の「同じ向きに並んだものは均等にする」と同じ）。`balance` は木全体にかけるので、向きを変えなかった節の割合（境界のドラッグで変えていたもの）も均等に戻る

### サーバー

- ブラウザから送るメッセージを 3 つ足す
  - `swap-panes { tab, with }`: 自分の表示にある 2 つのタブの位置を入れ替える
  - `flip-split { split }`: 自分の表示にある節の 2 つの子を入れ替える
  - `rotate-split { split }`: 自分の表示にある節の向きを変え、割合を均等に戻す
- `tab`・`with`・`split` が文字列のものだけを受け付ける。自分の表示にないタブ、同じタブどうし、自分の表示にない節は無視する（表示を配り直さない）。どれも葉の数を変えないので、並べられる数（3 つ）を超えることはない
- ほかの表示の変更と同じく、変えた表示は本人と、ペアプロモードで本人に追従している人に配る。追従している人が自分で変えたら、ペアプロモードをやめる（ブラウザが先にやめたことを送り、サーバーも表示を変える操作を受けたらやめたものとする。docs/adr/100-terminal-tabs.md）

## 理由

- 1 を C: ドラッグは「これとこれ」を直接選べるので、2 つのタブの入れ替えが分かりやすい。メニューは、対象のタブを 1 つしか選べないので、「左右」「上下」の入れ替えにする。2 つ並べているときは、どちらでも同じ結果になる
- 2 を B: 3 つ並べているときに、一番外だけを変えると、内側の 2 つの向きを変えられない。操作したターミナルに一番近い節を変えれば、2 つ並べたものの「左右を上下に」が、3 つのときもそのまま当てはまる。外側の節は、境界の右クリックで選べる
- 向きを変えたら均等に戻す: 向きを変えると、同じ向きに並ぶものの組み合わせが変わる（左 1・右に上下 2 つ → 左右に 3 つ）。割合を残すと、3 つ並んだときに 50 / 25 / 25 になり、#100 で均等にしたのと同じ問題が出る
- 3 を A: タブの並べ替え（docs/adr/139-tab-order.md）は全員で共有するタブの一覧の順で、表示の並び（参加者ごと）とは別のもの。ドラッグを始める場所（一覧のタブか、ターミナルのバーか）で分けると、どちらの操作かが混ざらない。ドラッグを受け付ける先も、それぞれのページの中のものだけにする（サイドメニューはターミナルのバーのドラッグを、ターミナルはタブのドラッグを受け付けない。ファイルのドロップはこれまでどおり）。B は、タブを表示に加える操作（⌘ / Ctrl を押しながら選ぶ）と区別しにくい
- 4 を B: 木を送ると、受け取ったときの表示と食い違っていないか（知らないタブ・節がないか、葉が 3 つまでか）を確かめる必要がある。操作を送れば、サーバーは今の表示にある節・タブかを確かめるだけで済み、ペアプロモードの間に相手の表示が写って木が変わっていても、ないものは無視される

## docs/adr/100-terminal-tabs.md との関係

- 分割の木、参加者ごとの表示、ペアプロモードで写すこと、自分で表示を変えたらやめることは、そのまま使う。表示を変える操作に、位置の入れ替えと向きの変更を足す
- 「同じ向きに並んだものは均等にする」を、向きの変更にも当てはめる。左右・上下の入れ替えでは、大きさは中身と一緒に動く（割合を 1 − 割合にする）。2 つのタブの入れ替え（ドラッグ）では、節の割合はそのままで、大きさは場所に残る
- docs/adr/139-tab-order.md の「含めないもの」の「分割の中でのターミナルの位置の入れ替え」を、このストーリーで扱う

## 影響・今後の課題

- ターミナルのバーはつかんで動かせるようになる（カーソルが手の形になる）。バーのボタンや名前の上から始めたドラッグも、バーのドラッグになる
- 境界を右クリックしても、割合は変わらない

## 含めないもの

- ターミナルを別の場所（ほかのターミナルの上下左右など）へ移して、木の形そのものを変えること（入れ替えと向きの変更で 3 つまでの並べ方はすべて作れる）
- 4 つ以上並べること
- 入れ替え・向きの変更のショートカット（別の Issue で扱う）
