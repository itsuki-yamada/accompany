# 直前に実行したコマンドの出力を、ひと操作でコピーする

- 日付: 2026-10-23（2026-10-27 に、右下のボタン・activate・ショートカットの扱いを改めた）
- ストーリー: #112

## 背景

herdr のように、特定のターミナルの情報をすぐ取り出して、ほかの人やエージェントに渡したい。特に「直前に実行したコマンドの出力」をひと操作でコピーしたい。コピーは、その操作をした参加者のブラウザのクリップボードに入れ、ほかの参加者には入れない。

実装の途中で、利用者から「copyボタンを右下に用意しておいてショートカットかcopyを押してクリップボードに直近の結果がコピーされるイメージでした」と要望があった。右クリックのメニューだけでは見つけにくいので、いつも見えているボタンを置く。OSC 52（コマンドがクリップボードに書く）で入れる案（#113）は見送り、このストーリーにまとめた。

さらに、シェルの統合の入れ方は「入れるとしたらmiseとかのactivate関数を参考にしたい」、ショートカットは「別issueを切ろうと思うのでこれからの開発では一旦なしでいいです。マウスファーストにしておいてください」と要望があった。

決める必要があったのは次のこと。

- コマンドの区切りの見分け方
- 区切りをどこで覚えるか（ブラウザだけか、サーバー側の画面でも覚えるか）
- シェルが区切りの印を出すようにする方法と、対応するシェル
- シェルの統合がないときの扱い
- 操作（ボタン・メニュー）と、何をコピーしたかの見せ方

## 検討した選択肢

### コマンドの区切り

1. シェルの統合（OSC 133）の印で見分ける。A（プロンプトの始まり）、B（コマンドの始まり）、C（出力の始まり）、D（出力の終わり）
2. プロンプトの文字列（`$ ` など）を画面から探す

### 区切りを覚える場所

1. ブラウザ（`@xterm/xterm`）だけで覚える
2. サーバー側の画面（`@xterm/headless`）でも覚え、つないだときに送る

### シェルが印を出すようにする方法

1. Accompany が起動するシェルに自動で差し込む（zsh は `ZDOTDIR` を一時的なディレクトリに替えて、そこの `.zshrc` から利用者の `.zshrc` を読む。bash は `--rcfile`、fish は `XDG_DATA_DIRS` の `vendor_conf.d`。VS Code・Ghostty・kitty などの方式）
2. 利用者が自分の rc に 1 行書いて入れる。スクリプトは Accompany が出す（`mise activate`・`starship init`・`zoxide init` などの方式）
3. README にスクリプトを載せ、利用者が写す

### CLI の形

1. オプション（`accompany --shell-integration zsh`）
2. `mise activate` と同じ形のサブコマンド（`accompany activate [シェル]`）

### ボタンの置き場所

1. ターミナルの表示の右下に重ねる
2. ペインの下に細い帯を設け、その右端に置く

## 決定

- コマンドの区切りは OSC 133 で見分ける（選択肢 1）。C を受け取った位置から、D（D を出さずに次の A を出すシェルもあるので、A でも終わりとみなす）を受け取った位置までを、直前のコマンドの出力とする。B は使わない
- 区切りは、ブラウザとサーバー側の画面の両方で覚える（選択肢 2）。仕組みは同じクラス（`src/command-marks.ts`）で、xterm.js の parser に OSC 133 のハンドラを登録し、C と D の位置を xterm の marker で覚える
  - つないだとき、サーバーは画面の書き出しの前に、覚えている範囲（直前のコマンドの出力、実行中のコマンドの出力の始まり、OSC 133 を受け取ったことがあるか）を、出力の始めからの行の番号（スクロールバックから押し出された行の数を足したもの。docs/adr/94-remote-selection.md と同じ数え方）で送る。ブラウザは、届いた画面を書き終えてから、その行に marker を置く
  - 書き終えるまでの間に受け取った印のほうが新しいので、届いた範囲はそれを上書きしない
- シェルの統合は、利用者が rc に 1 行書いて入れる（選択肢 2）。CLI は `mise activate` と同じ形のサブコマンド `accompany activate [シェル]` にする（選択肢 2）
  - zsh: `eval "$(accompany activate zsh)"`（`precmd_functions` の先頭と、`add-zsh-hook` の `preexec`）
  - bash 4.4 以上: `eval "$(accompany activate bash)"`（`PROMPT_COMMAND` の先頭と `PS0`。`PROMPT_COMMAND` は文字列でも配列でもよい）
  - fish: `accompany activate fish | source`（`fish_preexec`・`fish_postexec`・`fish_prompt` のイベントの関数）。fish 4.0 以上は自分で OSC 133 を出すので、書かなくてもよい
  - シェルを省くと `$SHELL` の名前から決める。知らないシェル（指定したもの、または `$SHELL`）なら、対応しているシェルを示して終了コード 1 で終わる
  - `mise activate` の作法にならう: フックの名前は `_accompany_hook`（・`_accompany_hook_preexec` など）にそろえ、スクリプトは前に読み込んだフックを外してから入れ直す（何度読み込んでも 1 回分だけ効き、新しい版のスクリプトで入れ直せる）。`accompany activate --help` は、出力をシェルで評価して使うこと、どの設定ファイルに書くか、シェルごとの書き方の例を示す。全体の `--help` にも `activate` を載せる
  - スクリプトはプロンプト（PS1 など）を書き換えない。印は C・D・A だけを出す。`mise activate` と違い、環境変数（`MISE_SHELL` にあたるもの）は書き出さない（使い道がないため）
  - `activate` という名前のコマンドを最初のターミナルで動かすときは、`accompany -- activate` と書く。サブコマンドとみなすのは、最初の引数が `activate` のときだけ
- シェルの統合がない（OSC 133 を一度も受け取っていない）ときは、ボタンとメニューの項目を押せなくし、メニューでは「シェルの統合が要ります」と横に出す。ツールチップに入れ方（`eval "$(accompany activate zsh)"` など）を出す。押せない見た目のボタンを押したときは、コピーせずに同じ説明を知らせる。まだコマンドを実行していないとき（出力がスクロールバックから押し出されたときも）と、全画面のアプリの中（代替画面）も、同じように押せなくして理由を出す
- 操作は、各ペインの右下の「⧉ コピー」のボタンと、右クリックのメニューの「直前のコマンドの出力をコピー」（「コピー」の下）。マウスで操作する
  - ショートカットは別の Issue で扱う。まずはマウスで操作できるようにする
  - ボタンは、ペインの下の細い帯の右端に置く（選択肢 2）。ターミナルの表示には重ねない。小さく薄くし、マウスを乗せたときだけはっきり出す。押してもキー入力の先はターミナルのまま
  - コピーできないとき（下記）は、ボタンを押せない見た目（`aria-disabled`）にし、マウスを乗せると理由がツールチップに出る。`disabled` にしないのは、押せないボタンにもツールチップを出し、押したら理由を知らせるため。出力を書き終えるたびに、押せるかを見直す
  - 知らせ（コピーしたことや理由）は、ボタンに重ならないよう、帯の上に出す
- コピーすると、コピーした範囲を 0.8 秒だけ黄色く光らせ、「直前のコマンドの出力をコピーしました（N 行）」と知らせる。出力が空のときはコピーせず、「直前のコマンドは何も出力していません」と知らせる
- コピーはブラウザの中だけで行い、サーバーにもほかの参加者にも何も送らない
- 文字列は、行の右端の空白を除き、折り返した行は前の行につなぐ。末尾の改行は除く

## 理由

- **OSC 133**: プロンプトの文字列はシェルや利用者の設定ごとに違い、出力の中の同じ文字列と区別できない。OSC 133 は多くの端末（iTerm2・kitty・WezTerm・Ghostty・Windows Terminal・VS Code）とシェルの統合が使っている印で、fish 4.0 は自分で出す。ほかの統合が出す印もそのまま使える
- **サーバー側の画面でも覚える**: 画面の書き出し（`@xterm/addon-serialize`）は OSC 133 の印を含まないので、ブラウザだけで覚えると、途中から参加した人やページを読み込み直した人は、次にコマンドを実行するまでコピーできない。ペアプロでは、相手が実行したコマンドの出力をあとから参加した人がコピーしたい場面がある。サーバー側の画面はもともと途中から参加した人のために出力を反映しているので、ハンドラを 1 つ足すだけで済む
- **コピーはブラウザの中で行う**: 範囲を覚えていれば、文字列はブラウザの端末のバッファから読める。サーバーに問い合わせると、返事を待つ間にキーやクリックの「ユーザーの操作」の扱いが切れ、ブラウザによってはクリップボードに書けない。ほかの参加者のクリップボードに入れないことも、何も送らないことで保てる
- **rc に 1 行書く（自動で差し込まない）**: 利用者の方針は「既定の動作を変える前に確認する」「ラッパーではなく、ツール本体の設定で直す」。自動の差し込みは、`ZDOTDIR` の付け替えや `--rcfile` の差し替えで、利用者の rc の読み込みを Accompany が仲介することになる。rc の読み込み順や `ZDOTDIR` を前提にした設定（プラグインマネージャなど）を壊すことがあり、壊れても原因が見えにくい。`-- <コマンド>` で起動したシェルや、tmux の中のシェルには届かない。rc に書けば、シェル自身の設定として、どこから起動しても同じように効く。Accompany の外の端末で読み込んでも、OSC 133 を知らない端末は印を無視し、知っている端末はむしろ活用する
- **`mise activate` と同じ形のサブコマンドにする（オプションをやめた）**: はじめは、`-- ` を付けずに書いた引数を最初のターミナルで動かすコマンドとして扱っている（`accompany vim` で vim が動く）ので、名前のぶつからないオプション（`--shell-integration`）にしていた。利用者の要望で、多くの人が rc に書き慣れている `mise activate` の形にそろえた。`eval "$(accompany activate zsh)"` は `eval "$(mise activate zsh)"` と同じに読め、シェルを省けば `$SHELL` から決まるのも同じ。代わりに、`accompany activate` で `activate` という名前のコマンドは動かせなくなるが、`accompany -- activate` で動かせる（`--` のあとは必ずコマンドとして扱う）。そうした名前のコマンドを `--` なしで動かしている人は、ほとんどいないとみる
- **bash は 4.4 以上**: コマンドを読んでから実行する前に出す `PS0` は 4.4 で入った。それより古い bash（macOS の `/bin/bash` は 3.2）では `DEBUG` の trap で代わりにできるが、`PROMPT_COMMAND` の中のコマンドにも反応するのを避ける工夫や、利用者の trap との衝突があり、複雑になる。macOS の既定のシェルは zsh なので、古い bash ではスクリプトは何もしない
- **B を使わない・プロンプトを書き換えない**: B を出すには PS1 の末尾に印を足す必要があり、プロンプトのテーマ（powerlevel10k など）が毎回 PS1 を作り直すと消える。直前のコマンドの出力には C と D があれば足りる
- **空の Enter**: zsh の `preexec`、bash の `PS0`、fish の `fish_preexec` は、空の行では動かない（bash 5.3 と zsh で確かめた）。D だけが届くので、直前のコマンドは変わらない
- **ショートカットを作らない**: 利用者の要望で、ショートカットは別の Issue でまとめて決める（ほかのストーリーで使うキーとのぶつかりも、そこで整理する）。まずはマウスで操作できるようにする
- **右下のボタン**: 利用者の要望。右クリックのメニューは、知らないと見つからない。いつも見えていれば、押すだけで直前の結果がコピーされると分かる。ほかのボタン（ペインのバー）とも離れている
- **下の帯に置く（表示に重ねない）**: はじめは表示の右下に重ねたが、端末の右下の文字がボタンの下に隠れて読めず、そこから選択も始められなかった（はみ出した端末の右下の文字が見えることを確かめる既存の E2E も落ちた）。帯の分（1 行に満たない高さ）だけ端末の行が減るが、出力を隠さないほうを選んだ。端末の大きさの下限の計算（docs/adr/99-smallest-size.md）では、ペインのバーと同じく帯の高さも引く
- **光らせる**: 何がコピーされたかは、クリップボードの中を見ないと分からない。範囲を一瞬光らせれば、どこからどこまでをコピーしたかがすぐ分かる。行の数も知らせる

## 影響・今後の課題

- 利用者が rc に 1 行書くまでは使えない。ボタン・メニューのツールチップと知らせで入れ方を案内する
- 各ペインの下に帯が増え、端末の表示領域が少し（帯の高さの分）狭くなる
- `accompany activate` は、`activate` という名前のコマンドを動かすものではなくなった（`accompany -- activate` で動かす）
- ショートカット（キーボードでのコピー）は含めない。別の Issue で扱う
- 代替画面（全画面の TUI）の中の印は扱わない。代替画面を表示している間はコピーできない。全画面のアプリが終わったあとは、そのコマンド（通常の画面には何も出していないことが多い）が直前のものになる
- 再起動したとき（docs/adr/34-session-restore.md）に戻すスクロールバックには印が含まれないので、再起動の前のコマンドの出力はコピーできない。印を保存することは含めない
- 途中から参加したときに代替画面を表示していると、届いた範囲を覚えない（marker は表示中の画面にしか置けないため）
- 端末の大きさの変更で行が折り返し直されると、範囲の列がずれることがある
- `clear` などで画面を消したあとは、消えた行の文字は読めない（範囲が残っていても、空や別の文字になる）
- marker は xterm の公開の API だが、行の押し出しの数え方は内部の API（`src/trimmed-lines.ts`）を使っている。xterm.js を上げるときは E2E（`e2e/tests/command-output.spec.ts`）で確かめる
- zsh の E2E は、zsh が入っている環境（macOS のローカルなど）でだけ流す。CI の Linux に zsh がなければ飛ばす。fish はスクリプトを出すことだけを確かめ、実際の fish では確かめていない
- ほかに取り出せるとよい情報（含めない。必要になったら別のストーリーにする）
  - 直前に実行したコマンドの行そのもの（B から C まで。PS1 に B を足す必要がある）
  - 直前のコマンドの終了コード（D の引数）を、ターミナルのバーに出す
  - 直前のコマンドとその出力をまとめて（Markdown のコードブロックとして）コピーする
  - カレントディレクトリ（OSC 7）や、選択範囲・画面全体の文字列を、エージェントに渡しやすい形でコピーする
