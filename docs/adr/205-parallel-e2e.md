# E2E をワーカーごとにポートをずらして並行に流す

- 日付: 2026-10-29
- ストーリー: #205

## 背景

プルリクの E2E は、どのジョブも「E2E を実行する」に 8〜9 分かかっていた（run 40816414532 で 474〜549 秒）。Playwright を `workers: 1` で流していたためで、並行にしていなかったのは、テストどうしが同じポートで Accompany を起動するからだった。

ポートは `e2e/tests/accompany.ts` の `testPort(offset)` で、`E2E_PORT_BASE`（既定 3000）からのずれで決めている。テストが使う offset は 0〜3、ポートが埋まっているときの確かめで 2〜11、Accompany 以外のサーバーで 50。Accompany は、指定したポートが使われていると、続く 10 個まで順に試す。

## 検討した選択肢

- A. ワーカーごとに、`E2E_PORT_BASE + TEST_PARALLEL_INDEX × 幅` からポートを使う
- B. どのテストもポート 0 で起動し、起動の出力からポートを読む
- C. 並行にせず、CI のジョブを shard で分ける

## 決定

A を採る。

- 幅は 100 にする。今の offset の最大（50）と、Accompany が埋まったポートを避けて進む分（+10）より十分広い。`testPort` は、幅以上の offset を渡されたら例外にする
- `TEST_PARALLEL_INDEX` は 0 から（ワーカー数 - 1）までの番号で、落ちて起動し直したワーカーも同じ番号を使う。`TEST_WORKER_INDEX` は起動し直すたびに増えるので使わない
- 並行の単位はファイル（`fullyParallel` は使わない）。同じファイルのテストは、`let accompany` などをテストのあいだで共有しているので、これまでどおり順に流す
- ワーカー数は、CI では CPU のコアの数（`"100%"`。ubuntu-latest は公開リポジトリで 4 コア）、手元ではコアの半分（`"50%"`）にする
- tarball を `bunx --package` で起動するときは、最初の起動でパッケージを入れるので、`globalSetup` で 1 回 `--version` を動かしてから流す

ポート以外にぶつかるものは見当たらなかった。一時ファイルと保存先（`ACCOMPANY_STATE_DIR`）は、どのテストも `mkdtemp` で使い捨てのディレクトリを作っている。プロセスの操作は、起動したプロセスグループだけを対象にしている。クリップボードは、ワーカーごとに別の Chromium の中で閉じている。

端末の大きさを表示する偽のコマンド（`e2e/fixtures/corner-reporter.ts`・`size-reporter.ts`）は、並行にして負荷が上がると、起動直後に Accompany が PTY の大きさを変えても 80x24 のまま描き直さないことがあった（CI で 1 回）。Bun の `process.stdout` は、起動時に大きさを読んでから SIGWINCH を受けられるようになるまでに少し間があり、その間に届いた SIGWINCH を捨てるためと見ている。そこで、描き直しを `process.stdout` の `resize` で行い、`_refreshSize()` で PTY の実際の大きさを 100ms ごとに読み直す。読み直すのは PTY の大きさ（ioctl）なので、「Accompany が PTY の大きさを変える」ことはこれまでどおり確かめている。

## 理由

- A は、今の `E2E_PORT_BASE` と `testPort` の仕組みのまま、ワーカーの番号を足すだけで済む。`--port` を確かめるテストや、埋まったポートを確かめるテストも、そのまま決まったポートで書ける
- B は、ポートを決める方法が 2 つになり、決まったポートを使うテストが残る（docs/adr/145-wait-port-free.md の B と同じ理由）
- C は、ジョブの数（ランナー）が target × shard に増え、準備（依存のインストール、tarball・実行ファイルの作成、Chromium の取得）を shard の数だけ繰り返す
- コアの数より多いワーカーは、Accompany・シェル・Chromium・動画の書き出しを奪い合うだけで速くならず、待ち時間の短い確認が落ちやすくなる

## 結果

- 手元で複数の作業ディレクトリから E2E を流すときは、`E2E_PORT_BASE` を、ワーカー数 × 100 以上離す
- テストで新しく決まったポートを使うときは、`testPort` の offset を 100 未満で使う
