# エージェントが作業中か入力待ちかを、出力の続き方から判定する

- 日付: 2026-10-14
- ストーリー: #28

## 背景

ターミナルのバーに、そこで動いているエージェントが「作業中」か「入力待ち」かを出し、作業が終わったらブラウザの通知で知らせたい。参加者全員が同じ表示を見るため、状態はサーバーが判定して配る。

判定の手がかりとして、次のものが考えられる。

- PTY の出力の有無と経過時間
- エージェントが出す通知のシーケンス（BEL `\x07`、OSC 9、OSC 777）
- Claude Code の hooks（`Stop`、`Notification` など）

実物の Claude Code（プロンプトは送らない）を PTY で起動して出力の時刻を記録したところ、次のようだった。

- 起動直後の約 1.5 秒は、画面の描画で出力が続く
- 入力待ちになると出力はほぼ止まる（約 10 秒後に 1 回、小さな再描画があっただけ）
- 起動時に OSC 11 や OSC 7501 の問い合わせで BEL を終端に使う。BEL は通知以外の用途でも出てくる

## 検討した選択肢

1. **出力の有無と経過時間で判定する**: 出力が続いている間は作業中、一定時間出力がなければ入力待ち
2. **BEL / OSC 9 / OSC 777 で判定する**: エージェントが「終わった」と知らせるシーケンスを拾う
3. **Claude Code の hooks で判定する**: hooks から Accompany に状態を送ってもらう

## 決定

選択肢 1 を採る。判定の規則は次のとおり。

- 参加者が打った入力のあとに出始めた出力だけを数える
  - 入力から 2 秒以内に出始めた出力だけを数える。出力のないまま 2 秒たったら、その入力では判定しない
  - 入力から 0.2 秒以内の出力は、入力の表示（エコー）とみなして数えない
- 数える出力が、2 秒以上途切れずに 1 秒以上続いたら「作業中」
- 出力が 2 秒途切れたら「入力待ち」。次に入力があるまで、出力が出ても作業中にしない
- ターミナルを開いた直後は「入力待ち」

「参加者が打った入力」は、制御シーケンス（CSI、SS3、OSC・DCS・APC・PM・SOS、X10 形式のマウスの報告）を取り除いたあとに、表示できる文字か CR が残る入力とする。ブラウザの端末（xterm.js）は、端末への問い合わせ（OSC 11 の背景色、DA など）に自動で応答し、その応答は打鍵と同じ経路（`onData`）でサーバーに届く。Claude Code は起動時に問い合わせを出すので、応答まで入力として数えると、ページを開いただけで起動直後の描画が数えられ、「作業中」→「入力待ち」と通知が出てしまう。フォーカスの報告（`CSI I` / `CSI O`）やマウスの報告（Claude Code はマウスの追跡を有効にする）も同じ理由で数えない。矢印キーは、TUI がアプリケーションカーソルモードにしていると SS3（`ESC O A` など）で届き、F1〜F4 はいつも SS3（`ESC O P` など）で届くので、SS3 も取り除く。

状態はターミナルごとにサーバーが持ち、変わるたびに配置用の WebSocket（`/ws/workspace`）で全員に配る。途中から参加した人にも、参加したときに今の状態を送る。

通知は次のようにする。

- 作業中から入力待ちに変わったとき、各参加者のブラウザが、その参加者がそのターミナルを見ていなければ通知を出す。「見ていない」は、ページが見えていない（`document.hidden`）か、そのターミナルが表示中のタブにない（表示していないタブのターミナル）か、その参加者が別のターミナルにフォーカスしていること
- `document.hasFocus()`（ウィンドウが前面か）は条件に入れない。ウィンドウが背面でも画面が見えていれば状態の表示で気づけるため、通知を増やさない
- 通知をクリックすると、ブラウザのウィンドウとそのターミナルにフォーカスを移す。ほかのタブのターミナルなら、そのタブに切り替えてからフォーカスする。表示中のタブは参加者全員で共有している（[ADR 21](21-tabs.md)）ので、全員の画面が切り替わる
- 通知の許可は、ページを開いただけでは求めない。ページを最初に操作したとき（クリックやキー入力）に、まだ決まっていなければ（`default`）1 回だけ求める。許可されなかったら、そのページを開き直すまで求めない
- 許可されていなければ通知は出さない（バーの表示だけ）

## 理由

- **利用者に設定を求めない**: 選択肢 1 は、エージェントが何であっても出力さえあれば動く。選択肢 2 は Claude Code では通知の出し方の設定（`preferredNotifChannel`）に依存し、既定では出ないことがある。選択肢 3 は利用者に hooks の設定と、Accompany への送り先（ポートや認証）を求める
- **E2E で確かめられる**: 偽のエージェント（`e2e/fixtures/busy-agent.ts`）で、出力を出してから止まる動きを再現すれば確かめられる
- **BEL は紛らわしい**: OSC の終端としても使われるため、BEL だけを拾うと起動時の問い合わせで「終わった」と誤判定する
- **入力のあとだけ数える理由**: Claude Code は起動時に 1.5 秒ほど描画を続けるので、出力の長さだけでは起動直後に作業中になり、すぐ入力待ちの通知が出てしまう。エージェントの作業は参加者の入力（プロンプトや承認）から始まるので、入力のあとの出力だけを数えれば十分
- **打鍵かどうかをサーバーで見分ける理由**: ブラウザ側で xterm.js の自動応答と打鍵を分けて送る方法もあるが、xterm.js の `onData` は両者を区別しないため、キー入力やペーストのイベントを別に追う必要があり、ブラウザとサーバーの両方に手が入る。サーバーで入力の中身を見れば、判定に関わることが `activity.ts` の中だけで済む
- **入力から 2 秒で判定をやめる理由**: 入力しても出力がなかったとき（たとえば何も起きないキー）に判定を続けると、ずっとあとに入力と関係なく出た出力で「作業中」になってしまう
- **1 秒続いたら作業中にする理由**: `ls` のような短いコマンドの出力や、タイピングのエコーで作業中になると、すぐに入力待ちの通知が出て煩わしい
- **2 秒で入力待ちにする理由**: Claude Code は作業中、スピナーと経過時間を描き続けるので、2 秒も出力が途切れることはない。待ちすぎると通知が遅れる

## 影響・今後の課題

- 出力を出さずに長く動く処理（出力のない長いコマンドなど）は、作業中と判定できない。逆に、入力のあとに長く出力し続けるもの（ビルドのログなど）は、エージェントでなくても作業中になる。シェルで長いコマンドを流して終わったときに通知が来るのは、むしろ便利なことが多いと考えて許容する
- Claude Code が許可を求めて止まったときも、出力が止まるので「入力待ち」になり通知が出る。これは参加者に知らせたい場面なので望ましい
- 矢印キーや Esc、Ctrl+C のような、制御シーケンスや制御文字だけの打鍵は数えない。Claude Code では、選択肢を矢印キーで選んでも Enter（CR）で確定するので、確定したところから数えられる
- 判定の時間（0.2 秒・1 秒・2 秒）は固定にしている。不便があれば設定できるようにする
- より正確にしたくなったら、選択肢 2・3 を「利用者が設定すれば使える追加の手がかり」として足せる。そのときも、何も設定していない利用者には選択肢 1 で動くようにする
- 通知のクリックによるタブの切り替えは全員の画面に効くので、複数の参加者が別々のタブの通知をクリックすると、表示中のタブを取り合うことがある。タブを参加者ごとに選べるようにするときに見直す
- 通知を受け取るかどうかを切り替える画面はない。ブラウザのサイト設定で止められる
