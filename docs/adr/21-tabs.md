# タブを Workspace に持たせ、配置の配信を tabs イベントに置き換える

- 日付: 2026-10-14
- ストーリー: #21

## 背景

タブを開いて複数のターミナルを切り替えて使えるようにする。ユーザーと次のことを決めた。

- タブの並びと表示中のタブは、参加者全員で共有する（画面分割と同じく「全員で同じ画面」）
- 各タブは独立した分割の配置を持つ。新しいタブは $SHELL のターミナル 1 つで始まる
- 最後のタブは閉じられない。タブの最後のターミナルのシェルが終了したらタブを閉じる（最後のタブならターミナルは残す）

これまでサーバーの `Workspace` は分割の配置（`layout`）を 1 つだけ持ち、`/ws/workspace` で `{ type: "layout", layout }` を配っていた。タブを入れるには、この構造と配信の形を変える必要がある。#27・#28・#29 も同時に実装されているため、変更点をここに残す。

## 検討した選択肢

### サーバーの構造

1. `Workspace` が `tabs: Tab[]`（`Tab = { id, name, layout }`）と表示中のタブ `active` を持つ
2. 分割のツリーの根に「タブ」の節を足し、1 つのツリーで表す
3. タブごとに `Workspace` を作る

### 配信の形

1. `layout` イベントを `{ type: "tabs", tabs, active }` に置き換え、タブ一覧と全タブの配置をまとめて配る
2. `layout` イベントはそのまま（表示中のタブの配置）にし、`tabs` イベントを別に足す

### 表示していないタブのターミナル（ブラウザ側）

1. 表示中のタブのペインだけを作り、ほかのタブのペインは破棄する（接続も切る）。戻ったときは途中参加と同じ仕組み（#6）で画面を復元する
2. 全タブのペインを作っておき、表示していないものを隠す

## 決定

- サーバー: 選択肢 1。`Workspace` に `tabs` と `active` を持たせ、分割・閉じる・割合の変更は、対象のターミナル（分割の節）を含むタブの配置に対して行う。ターミナルの一覧（`terminals`）と参加者のフォーカス（`Member.terminal`）は、これまでどおり `Workspace` 全体で 1 つ
- 配信: 選択肢 1。`layout` イベントはなくし、`{ type: "tabs", tabs: Tab[], active: string }` を配る
- ブラウザから送るメッセージに `new-tab`、`select-tab { tab }`、`close-tab { tab }` を足す
- ターミナルの `close`（閉じるボタン、シェルの終了）は、タブの最後のターミナルならタブごと閉じる（`closeTab`）。最後のタブの最後のターミナルは閉じない
- タブの番号はターミナルと同じく、閉じても詰めずに 1, 2, 3 と続ける。名前は「タブ N」
- ブラウザ側: 選択肢 1。表示中のタブの配置だけを組み立てる

## 理由

- 構造: タブの一覧と分割のツリーは役割が違い、分けて持つ方が素直。ツリーに混ぜると、分割の処理（最後の 1 つは閉じない、など）がタブの節を意識する必要が出る。タブごとに `Workspace` を作ると、参加者とフォーカスの管理が分かれてしまう
- 配信: タブの切り替えと配置の変更は同じ「全員で同じ画面」の状態なので、1 つのイベントにまとめると、届く順番や片方だけ届いた状態を考えなくてよい。全タブの配置を配っても大きさは小さい
- ブラウザ側: 表示していないタブのターミナルを隠しておくと、そのターミナルの表示領域が 0 になり、端末の大きさの調整（#5）で扱いを考える必要がある。接続を切れば、その参加者は大きさの計算から外れるだけで済み、途中参加の復元（#6）がそのまま使える。フォーカス表示（#22）も、表示中のペインに対して出すだけでよい

## 影響・今後の課題

- `/ws/workspace` の `layout` イベントを受けていたコードは、`tabs` イベントの `tabs.find((t) => t.id === active).layout` を使う形に直す必要がある（同時に進んでいる #27・#28・#29 で配置のイベントを扱う場合）
- `Workspace.layout` はなくなった。配置は `Workspace.tabs[].layout` にある
- タブを切り替えると、表示していたターミナルの xterm は破棄され、戻ったときにサーバー側の画面から復元される。ブラウザ側の選択範囲やスクロール位置は切り替えをまたいで残らない
- 表示していないタブのターミナルは、どの参加者もつながっていなければ最後の大きさのまま動き続ける
- キーボードショートカット（#31）、タブにタイトルを出すこと（#32）は別のストーリーで扱う
