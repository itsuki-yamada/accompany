# 参加者の名前

- 日付: 2026-10-22
- ストーリー: #96

## 背景

参加者は、接続した順に「参加者 1」「参加者 2」と呼ばれる。ペアプロの相手が誰なのかを、名前で分かるようにしたい。名前は、ターミナルのバー、ツールバーの参加者の一覧、サイドメニュー、ペアプロモードの表示（docs/adr/93-pair-mode.md）、選択範囲（docs/adr/94-remote-selection.md）など、多くの場所に出る。

迷ったのは、次の点。

1. 名前を設定する場所
2. 名前を覚えておく場所と、サーバーへの伝え方
3. 名前の検証をどこで、どこまでするか
4. 同じ名前の参加者がいるときの見分け方

## 検討した選択肢

1. 設定する場所
   - A. 表示の設定（⚙）の画面に、名前の欄を足す
   - B. ツールバーに自分の名前を出し、押すと名前の入力欄を出す
   - C. 初めて開いたときに名前を聞く
2. 覚えておく場所と伝え方
   - A. ブラウザ（localStorage）に保存し、つないだときに `{ type: "name", name }` で送る
   - B. A と同じく保存し、配置の WebSocket の URL（クエリ）に付けて送る
   - C. サーバーに保存する
3. 検証
   - A. サーバーで整える（制御文字などを除き、長さを切り詰める）。ブラウザは入力欄の長さだけを抑える
   - B. ブラウザで整え、サーバーは受け取ったまま配る
4. 同じ名前
   - A. 何もしない（色で見分ける）
   - B. サーバーが、同じ名前の参加者すべてに「名前（参加者 N）」と番号を添えて配る
   - C. あとから同じ名前にした人を受け付けない

## 決定

1 は A、2 は A、3 は A、4 は B を採る。

- 表示の設定の画面に「あなたの名前」の欄を足す。自分だけの設定（配色など）のあと、端末の大きさの下限の前に、線で分けて置く。名前を設定していないときは、入力欄の例（placeholder）に「参加者 N」を出す
- 入力欄を離れたとき（change）か Enter で、前後の空白を除き、32 文字（書記素）までに切り詰めて保存し、`{ type: "name", name }` でサーバーに送る。空なら保存した名前を消し、空の名前を送る
- ブラウザの localStorage（`accompany.name`）に保存する。読み書きは try/catch で囲み、保存できなくても開いている間は使う。つないだとき（WebSocket の open）に、保存した名前があれば送る
- サーバーは受け取った名前を整える（`app/server/src/member-name.ts` の `sanitizeName`）
  - タイトル（`sanitizeTitle`）と同じく、C0・C1 の制御文字と、双方向テキストの制御文字を取り除く。改行・タブにあたる文字は空白にする。対になっていないサロゲートも取り除く
  - 整える前に、極端に長い文字列を先に切り詰める（1024 単位。UTF-16）
  - 続いた空白を 1 つにまとめ、前後の空白を除き、32 文字までに切り詰める。文字は `Intl.Segmenter` で書記素（見た目の 1 文字）ごとに数え、絵文字の組み合わせを途中で切らない。ブラウザの入力欄も同じ数え方で切り詰める（`maxLength` は UTF-16 の単位で数えるので使わない）
  - 空になったとき、見えない文字（`\p{Default_Ignorable_Code_Point}`: ゼロ幅スペース・ZWNJ・BOM・タグ文字・ソフトハイフン・ハングルのフィラー・CGJ・異体字セレクタなど、空白、点字の空白 U+2800）だけのときは、名前を設定していないものとして「参加者 N」に戻す。見えない文字を名前から取り除きはしない（ZWJ でつないだ絵文字などを壊すため）
- サーバーは、参加者ごとに設定した名前を持ち、presence の `name` には画面に出す名前を入れて配る。同じ名前（設定していない人の「参加者 N」も含む）の参加者が 2 人以上いれば、その全員を「名前（参加者 N）」にする。同じ名前かは、NFKC で正規化し、見えない文字（`\p{Default_Ignorable_Code_Point}`）と結合文字（`\p{M}`）を除いて比べる（「ＡＢＣ」と「ABC」、「やまだ」と CGJ や VS16 を足した「やまだ」を同じ名前とみなす）
- ブラウザは、これまでどおり名前を `textContent` と属性（`aria-label` など）でだけ出す。長い名前でバーやツールバーが崩れ、ページが横にはみ出さないよう、名前のバッジは 12em で、ペアプロモードの表示（「〇〇の画面に追従中」「〇〇があなたの画面に追従中」）の中の名前は要素に分けて 10em で末尾を省き、全文はツールチップで見せる。ペアプロモードの表示そのものも、ツールバーに収まらなければ縮めて末尾を省く

## 理由

- 1: 表示の設定の画面は、すでに参加者ごとの設定（配色・フォントの大きさ）と、全員に効く設定（端末の大きさの下限）を置いている。ツールバーに入り口を足すより変更が小さく、設定を探す場所が 1 つで済む。初めて開いたときに聞くと、すぐ始めたいときの邪魔になる
- 2: 認証がないので、参加者を開き直しても同じ人だと分かるのはブラウザだけ。サーバーに保存しても、次に開いた人と結び付けられない。URL に付けるとつないだ直後から名前で出せるが、既定の名前が一瞬出るだけなので、ほかの制御メッセージと同じ形にそろえた
- 3: 名前はほかの参加者の画面に出るので、送ってくるブラウザを信じず、全員に配る前にサーバーで整える（タイトルを整えるのと同じ考え方）。localStorage を書き換えたり、WebSocket に直接送ったりしても、整えたものしか配られない。双方向テキストの制御文字は、表示の順を入れ替えてほかの名前や文言に見せかけられるので除く
- 4: 色は 6 色を順に使うので、7 人以上いると同じ色になる。番号を添えると、色が見分けにくい人にも、同じ色の人どうしでも分かる。サーバーで決めると、バー・サイドメニュー・ペアプロモードの表示など、どこでも同じ表記になる。名前を拒むと、あとから入った人がなぜ変えられないのか分からない

## 影響・今後の課題

- presence の参加者の `name` は、設定した名前そのものではなく、画面に出す名前（番号を添えたもの）になる。設定した名前はサーバーだけが持つ
- 名前を送る前の一瞬は、ほかの参加者の画面に「参加者 N」と出る
- 選択範囲の名前は、これまでどおり描いた要素の `data-member` にだけ付く（画面に文字としては出さない）
- 「やまだ（参加者 1）」のように、番号を添えた形をまねた名前は拒まない。番号はほかの人の既定の名前と同じ形なので見分けにくいが、色が違う。困る例が出たら、括弧や「参加者」で始まる名前を制限することを検討する
- 見えない文字を足したり、結合文字を足したりしてほかの人と同じに見せた名前は、同じ名前として番号が付く。そのぶん、結合文字だけが違う別の名前（ほかの言語の母音記号など）にも番号が付くことがある
- 抜けた参加者の既定の名前（たとえば「参加者 2」）は、ほかの参加者が名乗れる。その人がいる間に同じ名前を付けると番号が付いて見分けられるが、抜けたあとは番号が付かない。番号は付け直さないので、新しく入った人とはぶつからない
- 書記素の数え方は、サーバー（Bun）とブラウザが持つ Unicode のデータによって、新しい絵文字でわずかに違うことがある。サーバーの結果が配られる

## 含めないもの

- 参加者の色を自分で選ぶこと
- 認証や、参加者を名前で同じ人とみなすこと（開き直すと番号は変わる）
