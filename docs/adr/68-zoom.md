# フォーカスしているターミナルの拡大表示は、自分の画面だけの表示にし、端末の大きさは元の分割のまま伝える

- 日付: 2026-10-18
- ストーリー: #68

## 背景

端末の大きさは、参加者のうち一番大きい表示領域に合わせる（docs/adr/51-largest-size.md）。画面を分割していて、ほかの参加者のほうが表示領域が大きいと、自分の画面では分割した 1 枠に端末が収まらず、スクロールか縮小で見ることになる。tmux のズーム（prefix z）のように、フォーカスしているターミナルを自分の画面いっぱいに広げて見たい。ユーザーの要望は「各ユーザーごとに適用し、サーバー側には反映しない」。

次のことを決める必要があった。

- 拡大の状態をどこに持つか
- 拡大中に、端末の大きさとしてどの表示領域を伝えるか
- 隠すターミナルをどう扱うか
- 配置が変わったとき（分割・閉じる・タブの切り替え）にどうするか
- ショートカットのキー

## 検討した選択肢

### 拡大の状態

1. ブラウザだけに持つ（index.ts の変数）。サーバーには何も送らない
2. サーバーの配置に「拡大中のターミナル」を持たせ、全員で共有する

### 拡大中に伝える端末の大きさ

1. 拡大で広がった表示領域を伝える（tmux のズームと同じく、端末も大きくなる）
2. 元の分割での表示領域を伝え続ける
3. 拡大中は何も伝えない

### 隠すターミナル

1. CSS（`display: none`）で隠すだけにし、`Pane`（xterm と WebSocket）は残す
2. 配置から外して `Pane` を捨て、解除したときに作り直す

### ショートカットのキー

1. Z（tmux の prefix z にならう）
2. ほかの文字（M = Maximize など）

## 決定

- 状態: 選択肢 1。`index.ts` の `zoomed`（ターミナルの ID）に持つ。配置用の WebSocket には何も送らない
- 端末の大きさ: 選択肢 2。`Pane` は拡大していないときの表示領域（`splitArea`）を覚えておき、拡大中は、それとフォントの大きさから列数・行数を計算して伝える。拡大中にウィンドウの大きさを変えても伝える大きさは変わらず、解除したときに分割での表示領域で測り直して伝える。拡大で広がった表示領域は、表示（スクロールせずに見えること、「画面に収める」の縮小の倍率）にだけ使う
- 隠し方: 選択肢 1。`#workspace` と拡大中のペインに `data-zoomed` を付け、CSS で、拡大中のペインとそれを含む分割以外（ほかのペイン・境界）を `display: none` にし、残ったものの `flex` を `1 1 0` にしてタブの表示領域いっぱいに広げる。隠したペインは、表示領域が 0 になるので端末の大きさを伝えない（サーバーには隠す前の大きさが残る）
- 配置が変わったとき:
  - 拡大中のターミナルが閉じられた、タブが切り替わった（拡大中のターミナルが表示中のタブにない）、分割が 1 つになったときは、拡大を解除する。タブを戻しても拡大は戻さない
  - ほかのターミナルが閉じられたり、ほかの参加者が分割したりしても、拡大は続ける。増えたターミナルは隠れたまま
  - 自分が分割するとき（ボタン・メニュー・ショートカット）と、隣のターミナルへフォーカスを移すときは、拡大を解除してから行う（tmux と同じ。増えたターミナルや移る先が隠れないように）。通知をクリックして隠れているターミナルへ移るときも解除する
  - 分割していないときは拡大できない（ボタンとメニューの項目を選べなくし、ショートカットは何もしない。キーはシェルに渡さない）
- キー: 選択肢 1。⌘⇧Z / Ctrl+Shift+Z で切り替える（docs/adr/31-shortcuts.md の方式）。操作はバーのボタン（⤢、`aria-pressed` で状態を出す）と右クリックメニューの「拡大表示」／「拡大を解除」からもできる
- 表示: 拡大中は、ペインのバーに「拡大中（ほか N 個を非表示）」を出す

## 理由

- 状態をブラウザに持つ: 要望が参加者ごとの表示の切り替えで、サーバーに状態を増やさない方針（「表示の設定」と同じく、どう見えるかは参加者ごと。docs/adr/36-appearance.md）に合う
- 元の分割での大きさを伝える: 完了条件「拡大しても、端末の大きさはほかの参加者に影響しない」を満たすため。端末の大きさは一番大きい表示領域に合わせるので、拡大した広さを伝えると、自分が一番大きいときに全員の端末が大きくなり、ほかの参加者は分割した 1 枠でスクロールすることになる。何も伝えない（選択肢 3）と、拡大中にフォントの大きさを変えたときに、変えたあとの大きさで測り直せない。この拡大は「ほかの参加者の大きい端末を、スクロールせずに見る」ためのもので、端末を大きくする必要はない
- CSS で隠すだけにする: `Pane` を捨てると WebSocket を切り、解除したときに画面の復元と xterm の作り直しが起きる（描き直しで画面が崩れる・ちらつく）。隠している間も出力は受け取り続けるので、解除するとすぐに最新の画面が見える。配置の組み立て（`build`）を変えずに済み、ほかのストーリーの変更とぶつかりにくい
- Z: tmux（prefix z）に合わせる。Shift を付けるので、シェルの Ctrl+Z（サスペンド）とはぶつからない。macOS の Chrome では ⌘⇧Z は「編集 > やり直す」のメニューのキーだが、予約されたコマンド（`kReservedCommandIds`）ではないので、ページに届き、`preventDefault` でメニューの動作を止められる（Google ドキュメントなどもやり直しに使っている）。Windows / Linux の Chrome には Ctrl+Shift+Z のアクセラレータはない。ペインの中にキー入力の先があるときだけ効き、ほかの入力欄のやり直しは奪わない

## 影響・今後の課題

- 1 人で使っているときに拡大しても、端末は大きくならない（分割での大きさのまま、余白が出る）。tmux のズームとは違う。拡大中だけ大きくする（自分が一番大きいときだけ）などは、必要になれば検討する
- 拡大中にウィンドウを大きくしても、端末は大きくならない。解除すると合わせ直す
- 拡大の状態は保存しない。再読み込みやタブの切り替えで解除される
- ターミナルの中のプログラムには Ctrl+Shift+Z が届かなくなる（Shift なしの Ctrl+Z は届く）
