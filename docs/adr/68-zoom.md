# 枠に収まらないターミナルは自分の画面だけで自動で拡大し、端末の大きさは元の分割の枠で伝える

- 日付: 2026-10-18
- ストーリー: #68
- 状態: #126（docs/adr/126-no-zoom.md）で置き換えられた。自動の拡大とその切り替えはなくした

## 背景

端末の大きさは、参加者のうち一番大きい表示領域に合わせる（docs/adr/51-largest-size.md）。画面を分割していて、ほかの参加者のほうが表示領域が大きいと、自分の画面では分割した 1 枠に端末が収まらず、スクロールか縮小で見ることになる。

ユーザーとの相談で、次のように決まった（Issue #68 の本文）。

- 画面の大きさが参加者で異なるときのための機能として、分割した 1 枠に収まらない（スクロールバーが出る）ときは、フォーカスしているターミナルを自分の画面いっぱいに自動で拡大する。収まるようになったら元に戻る
- 拡大は参加者ごとの表示で、サーバーの配置やほかの参加者の画面には反映しない。フォロー（#69）では追従しない
- 拡大を一時的に外して分割の全体を見る／また拡大に戻す、を自分で切り替えられる

次のことを決める必要があった。

- 拡大の状態をどこに持つか
- 拡大中に、端末の大きさとしてどの表示領域を伝えるか（「収まるか」の判定とループしないこと）
- 拡大中のターミナルとほかのターミナルをどう表示するか
- 自分で拡大を外したあとの扱い
- 配置が変わったとき（分割・閉じる・タブの切り替え）の扱い
- 切り替えのショートカットのキー

## 検討した選択肢

### 拡大中に伝える端末の大きさ

1. 拡大で広がった表示領域を伝える（tmux のズームと同じく、端末も大きくなる）
2. 元の分割の枠の表示領域を伝え続ける

### 拡大の表示

1. 拡大中のペインを、タブの表示領域いっぱいに重ねて出す（`position: absolute`）。元の位置には同じ大きさの空の要素を置き、ほかのペインと境界は `visibility: hidden` で見えなくする
2. ほかのペインと境界を `display: none` にし、拡大中のペインを含む分割を `flex` で広げる
3. 拡大中のペインだけを配置から外して組み直し、ほかのペインは捨てる

### 自分で拡大を外したあと

1. 外した状態は、もう一度切り替えるまで続く（フォーカスを移しても拡大しない）
2. フォーカスを移したら、自動の拡大に戻る

## 決定

- 状態: ブラウザ（`index.ts`）だけに持つ。自分がフォーカスしているターミナル（`focusedTerminal`）、自分で拡大を外しているか（`zoomOff`）、拡大しているターミナル（`zoomed`）。配置用の WebSocket には何も送らない
- 拡大する条件: 分割していて（ターミナルが 2 つ以上）、自分で外しておらず、フォーカスしているターミナルが枠に収まらないとき。収まらないとは、端末の列数・行数に、設定したフォントの大きさでの 1 文字の幅・高さを掛けた大きさ（横はスクロールバーの 14px を足す）が、分割での自分の枠の表示領域より大きいこと（`Pane.overflows()`）。「画面に収める（縮小）」の設定のときも同じ条件で拡大する（縮小せずに済むか、縮小が小さくなる）
- 端末の大きさ: 選択肢 2。拡大中も、元の位置に置いた要素の大きさから、ペインのバーなどの分を引いた大きさを分割での枠の表示領域とし、それで列数・行数を計算してサーバーに伝える。「収まるか」の判定も同じ大きさで行う。拡大中にウィンドウの大きさを変えても、元の位置の要素は分割の配置どおりに大きさが変わるので、伝える大きさと判定は分割したときと同じになる
- 表示: 選択肢 1。`#workspace` と拡大中のペインに `data-zoomed` を付け、CSS で重ねる。拡大中のペインのバーに「拡大中」を出す（ツールチップに隠しているターミナルの数）
- 自動で拡大するのは、収まらない状態が 300ms 続いたときにする。収まるようになったら、すぐに戻す。フォーカスを移したときと自分で切り替えたときは、待たずに決める
- 隣のターミナルへのフォーカスの移動（⌘⇧/Ctrl+Shift+矢印）は、拡大中も使える。向きは、元の位置の要素と、見えなくしているほかのペインの位置（分割の配置どおり）で決める。移る前に拡大を決め直し、移った先が収まらなければそのターミナルを拡大する
- 自分で切り替える: 選択肢 1。拡大しているターミナルで切り替えると外し、そうでなければ拡大に戻す。外している間は、フォーカスしているターミナルが収まらなければ、バーに「拡大を外しています」を出す。切り替えは、ショートカット（⌘⇧Z / Ctrl+Shift+Z）、ペインのバーのボタン（⤢、`aria-pressed` で拡大中かを出す）、右クリックメニューの「拡大を解除」／「拡大表示」でできる。拡大しておらず、枠に収まっているターミナルでは選べない（ショートカットは何もしないが、キーはシェルに渡さない）
- 配置が変わったとき: 組み直すたびに拡大を決め直す。拡大中のターミナルが閉じられた・タブが切り替わった・分割が 1 つになったときは拡大しない。ほかのターミナルが閉じられたり、ほかの参加者が分割したりしても、フォーカスしているターミナルが収まらなければ拡大を続ける（増えたターミナルは見えないまま）。拡大していたときは、待たずに置き直す

## 理由

- 状態をブラウザに持つ: 要望が参加者ごとの表示で、サーバーに状態を増やさない方針（表示の設定と同じく、どう見えるかは参加者ごと。docs/adr/36-appearance.md）に合う
- 元の分割の枠の大きさを伝える: 拡大した広さを伝えると、自分が一番大きい表示領域のとき、自分の拡大で全員の端末が大きくなり、ほかの参加者の枠に収まらなくなる（完了条件「端末の大きさはほかの参加者に影響しない」に反する）。また、伝えた大きさで端末が大きくなると、自分の枠にも収まらなくなって拡大が続き、判定がぐらつく。判定と伝える大きさを、どちらも拡大に左右されない分割の枠の大きさにすれば、拡大してもしなくても同じ値になり、ループしない。この拡大は「ほかの参加者の大きい端末を、スクロールせずに見る」ためのもので、端末を大きくする必要はない
- 重ねて出す（選択肢 1）: 元の位置の要素があるので、拡大中も分割での枠の大きさを測れる（ウィンドウの大きさを変えたときに「収まるようになった」を判定できる）。ほかのペインは大きさを保ったまま見えなくするだけなので、それぞれの大きさの計算・接続・xterm に影響しない。選択肢 2 は、拡大中に分割での枠の大きさが分からなくなり、隠したペインの大きさが 0 になる。選択肢 3 は、WebSocket を切って解除のたびに画面の復元と xterm の作り直しが起きる（描き直しで画面が崩れる・ちらつく）。どちらも配置の組み立て（`build`）を変えずに済み、ほかのストーリーの変更ともぶつかりにくい
- 300ms 待つ: 分割した直後やウィンドウの大きさを変えた直後は、自分の枠に合わせた大きさを伝えてから端末の大きさが変わるまでの間、一瞬だけ枠に収まらない。そのたびに拡大して戻ると画面がちらつく。待つのは拡大するときだけにし、戻すときは待たない
- 外したままにする（選択肢 1）: tmux のズームと同じく、自分で決めた表示が、フォーカスの移動や端末の大きさの変化で勝手に変わらないようにする。外していることはバーの表示で分かり、同じ操作で戻せる
- Z: tmux（prefix z）に合わせる。Shift を付けるので、シェルの Ctrl+Z（サスペンド）とはぶつからない。macOS の Chrome では ⌘⇧Z は「編集 > やり直す」のメニューのキーだが、予約されたコマンド（`kReservedCommandIds`、docs/adr/31-shortcuts.md）ではないので、ページに届き、`preventDefault` でメニューの動作を止められる（Google ドキュメントなどもやり直しに使っている）。Windows / Linux の Chrome には Ctrl+Shift+Z のアクセラレータはない。ペインの中にキー入力の先があるときだけ効き、ほかの入力欄のやり直しは奪わない

## このストーリーに含めないもの

- 枠に収まっているターミナルを、自分で拡大すること（tmux のズームのような、いつでも使える拡大）
- 外した状態を、フォーカスの移動や時間で自動の拡大に戻すこと
- 拡大の状態・外した状態を保存すること（再読み込みで自動の拡大に戻る）
- 拡大の状態をほかの参加者と共有すること、フォロー（#69）で追従すること
- 拡大中に、拡大した表示領域に合わせて端末を大きくすること
- ポップアップ（ほかのターミナルの上に小さく重ねて出す表示）

## 影響・今後の課題

- 分割した枠が狭いと、ペインのバーに全部のボタンが収まらないことがある（もとからある課題）。「拡大中」「拡大を外しています」の表示は、収まらない分を省略して、ボタンを押し出さないようにした
- ターミナルの中のプログラムには Ctrl+Shift+Z が届かなくなる（Shift なしの Ctrl+Z は届く）
- 列数と行数は別々に一番大きいものを取るので、横長の人と縦長の人がいると、両方とも枠に収まらず、両方の画面で拡大することがある
