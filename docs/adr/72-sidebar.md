# サイドメニューに Workspace とセッションの一覧を出し、「タブ」を「Workspace」と呼ぶ

- 日付: 2026-10-18
- ストーリー: #72

## 背景

タブや分割が増えると、どのターミナルでエージェントが作業中か、どれが入力を待っているかを探すのに手間がかかる。ユーザーの要望は「エージェントのセッションを一覧で見る、入力待ちのセッションを一覧から選んで飛ぶ」で、イメージは [herdr](https://herdr.dev/docs/concepts/) のサイドメニュー（上に Workspace の一覧と、それぞれの中のエージェントの状態をまとめた印、下に選択中の Workspace のエージェントの一覧）。あわせて、いまの「タブ」を「Workspace」と呼ぶ（英語のまま）。

一覧に必要な情報（全タブの配置、ターミナルのタイトル、エージェントの状態、参加者のフォーカス先）は、すでに配置用の WebSocket で全員のブラウザに届いている。

## 検討した選択肢

1. 一覧の出し方
   - a. ショートカットで開くポップオーバーの一覧（最初に作りかけた形。仕様の変更で取りやめ）
   - b. 画面の横の、出す・隠すを切り替えられるサイドメニュー
2. サイドメニューの下側（セッションの一覧）に出す範囲
   - a. herdr と同じく、表示中の Workspace のターミナルだけ
   - b. すべての Workspace のターミナルを、Workspace ごとにまとめて出す
3. いまの上のタブバー
   - a. 消して、すべてサイドメニューに移す
   - b. 残し、Workspace の一覧・追加・閉じるだけをサイドメニューに移す
4. 「タブ」→「Workspace」の言い換えの範囲
   - a. 画面の表記だけ
   - b. コードの識別子（`tab`、`select-tab` など）とサーバーのメッセージ・保存形式まで

## 決定

- **1-b**。サイドメニューは画面の左に置き、既定で出す。出す・隠すはツールバーの「☰」ボタンと ⌘⇧S / Ctrl+Shift+S で切り替え、参加者ごとにブラウザ（`localStorage`）に覚える。サーバーには状態を足さない
- サイドメニューの上側は Workspace の一覧（`role="tablist"`、縦向き）。各行に、選ぶボタン・中のターミナルの状態の件数（「作業中 1」「入力待ち 2」。0 件の状態は出さない）・閉じるボタンを並べる。見出しの「+」で Workspace を追加する
- **2-b**。下側のセッションの一覧は、すべての Workspace のターミナルを、Workspace ごとのグループにまとめて、配置の順に並べる。各行に状態（作業中・入力待ち）、「ターミナル N」、タイトル、フォーカスしている参加者（自分は「あなた」）を出す。見出しに全体の件数（「作業中 N」「入力待ち N」）を出す。行を選ぶと、通知のクリックと同じ処理（`focusTerminal`）で、その Workspace に切り替えてそのターミナルにフォーカスする
- 並び順は状態で入れ替えない。状態が変わるたびに行が動くと、選ぼうとした行がずれるため。入力待ち・作業中は、行の印の色と Workspace ごとの件数で見つける
- キーボード: ⌘⇧E / Ctrl+Shift+E でサイドメニューへ移る（隠していれば出す）。自分がフォーカスしているターミナルの行に移る。サイドメニューの中では ↑↓ で Workspace とセッションの行を順に移り、Enter で選ぶ、Esc でターミナルに戻る。セッションを選ぶとそのターミナルに移る。Workspace をキーボードで選んだときは、続けてセッションを選べるようサイドメニューに残る（マウスで選んだときは、これまでどおり表示したターミナルにフォーカスする）
- **3-b**。上のバーは「ツールバー」として残し、サイドメニューの「☰」、表示中の Workspace の名前、ショートカットの一覧「⌨」、表示の設定「⚙」を置く。サイドメニューを隠しても、いまの Workspace が分かり、⌘⇧. / ⌘⇧, で切り替えられる
- **4-a**。画面の表記（ボタン、aria-label、ショートカットの一覧、README）は「Workspace」（例: 「Workspace 1」「新しい Workspace」）にする。サーバーが付ける名前も「Workspace N」にする（名前は保存せず id から作るので、前の保存ファイルから戻しても「Workspace N」になる）。コードの識別子、WebSocket のメッセージ（`tabs`、`select-tab`、`new-tab`、`close-tab`）、保存形式は `tab` のまま
- サイドメニューは新しいモジュール `public/sidebar.ts` にまとめ、`index.ts` には組み込みと、配られた状態を渡すだけを足す

## 理由

- **サイドメニュー（1-b）**: ユーザーのイメージ（herdr）に合わせた。常に見えていれば、開く操作なしに作業中・入力待ちが目に入る
- **すべての Workspace を出す（2-b）**: 元の要望は「入力待ちのセッションを一覧から選んで飛ぶ」。herdr は blocked（入力・承認待ち）や done（終わって未確認）を区別できるので、Workspace の印から目当ての Workspace を見つけられるが、Accompany の状態は作業中・入力待ちの 2 つだけで、ただのシェルも「入力待ち」になる。表示中の Workspace だけだと、別の Workspace の入力待ちへは 2 回の操作が要るので、全件を出して 1 回で移れるようにした。Workspace ごとにまとめるので、どの Workspace のターミナルかも分かる
- **ショートカットのキー**: S は Sidebar、E は VS Code のエクスプローラーへ移るキー（⌘⇧E）にならった。Chromium のキーの割り当て（`chrome/browser/ui/accelerator_table.cc`、`chrome/browser/global_keyboard_shortcuts_mac.mm`、`chrome/browser/ui/cocoa/accelerators_cocoa.mm`、`main_menu_builder.mm`）を確かめ、⌘⇧S・⌘⇧E・Ctrl+Shift+S・Ctrl+Shift+E はどの OS にも割り当てがないことを確認した（⌘S は保存、Ctrl+E は検索だが、Shift 付きは別のキー）。⌘⇧L / Ctrl+Shift+L は縦のタブの折りたたみ、⌘⇧B / Ctrl+Shift+B はブックマークバーに使われているので避けた。シェルとの衝突は docs/adr/31-shortcuts.md と同じ考え方（Shift なしの Ctrl+S / Ctrl+E はこれまでどおり届く）
- **タブバーを残す（3-b）**: 隠したときにも、いまの Workspace と切り替え手段が分かる必要がある。ツールバーに名前を出すのが一番単純で、⌨・⚙ の置き場所も変えずに済む
- **識別子は変えない（4-a）**: #68・#69・#70 が `index.ts`・`pane.ts`・サーバー周辺を並行して変えている。識別子やメッセージまで変えると衝突が大きく、保存形式の移行も要る。サーバーのクラス名 `Workspace`（全体を持つ）と画面の「Workspace」（タブ）が別物を指すことになるが、コードのコメントで「画面の表記は Workspace」と補う

## 影響・今後の課題

- サイドメニュー（幅 240px）の分だけ、ターミナルを並べる領域が狭くなり、各参加者が送る端末の大きさ（列数）も減る。隠すと広がる。E2E の「画面いっぱい」は、ターミナルを並べる領域（`main`）いっぱいの意味に改めた
- 「終わったがまだ見ていない（done）」や「承認待ち（blocked）」の区別は入れていない。別のストーリーで扱う。区別できるようになったら、Workspace の印をそれに合わせ、セッションの一覧を表示中の Workspace だけに絞る（herdr と同じ）ことも検討する
- エージェントとシェルを見分けて、エージェントだけを出すことはしていない（状態の判定はすべてのターミナルで同じ。docs/adr/28-agent-status.md）
- 表示中の Workspace は全員で共有しているので、セッションの一覧から別の Workspace のターミナルへ移ると、ほかの参加者の表示も切り替わる（通知のクリックと同じ）
- サイドメニューの幅は変えられない。必要になったら境界のドラッグを足す
