# タブを名前と色の付いたグループにまとめる

- 日付: 2026-10-29
- ストーリー: #209

## 背景

タブが増えると、どのタブが何の作業かを見分けにくい。Chrome のタブグループのように、関係するタブを名前と色の付いたグループにまとめたい。折りたたみとキーボードショートカットは作らない（マウスで操作する）。

タブの並び（docs/adr/139-tab-order.md）と名前（docs/adr/110-tab-name.md）はサーバーが持って全員で共有し、保存している。参加者ごとの表示（どのタブをどう並べて見るか。docs/adr/100-terminal-tabs.md、docs/adr/163-rearrange-panes.md）は別に持っている。

迷ったのは、次の点。

1. グループを全員で共有するか、参加者ごとにするか
2. グループとタブの並びの関係（グループのタブを続けて並べるか）
3. ドラッグでグループに出し入れする規則
4. 前・後ろへ移す操作（右クリックのメニュー、Alt+矢印）がグループの端でどう動くか
5. 並べて表示（参加者ごとの表示）との関係
6. 色の選び方
7. 既存のグループに加えるメニュー（メニューに入れ子がない）
8. サーバーへの伝え方と検証

## 検討した選択肢

1. 共有するか
   - A. サーバーが持ち、全員で共有して保存する
   - B. 参加者ごとにブラウザに覚えておく
2. 並びとの関係
   - A. グループのタブは必ず続けて並べる。グループの並びはタブの並びの中の位置で決まる
   - B. グループはタブの印（色）だけで、並びはばらばらでもよい
3. ドラッグの規則
   - A. 重ねたタブと同じグループに入る（グループの外のタブに重ねれば外れる）。ラベルの前半ならグループの前、後半ならグループの先頭
   - B. グループの境目に「外」と「中」の両方の落とし先を作る
4. 端での前・後ろへの移動
   - A. グループの端から外へ移すと、その場でグループから外れる。グループの外のタブは、隣のグループを飛び越える
   - B. 外のタブは隣のグループに入る（Chrome のキーボード操作に近い）
5. 並べて表示との関係
   - A. グループはタブの一覧の見た目だけで、参加者ごとの表示は変えない
   - B. グループを選ぶと、グループのタブを並べて表示する
6. 色
   - A. 決まった 8 色から選ぶ
   - B. 自由な色（カラーピッカー）
7. 既存のグループに加えるメニュー
   - A. グループごとに「グループ「名前」に追加」の項目を並べる
   - B. メニューに入れ子（サブメニュー）を作る
8. 伝え方
   - A. 操作（作る・加える・外す・移す・名前・色・解除・まとめて閉じる）を送り、サーバーが並びとグループを変える
   - B. グループとタブの並び全体を送る

## 決定

1 は A、2 は A、3 は A、4 は A、5 は A、6 は A、7 は A、8 は A を採る。

### 見た目

- サイドメニューでは、グループの最初のタブの上にラベル（グループの色の地に、暗い文字で名前）を出し、グループのタブは少し右に下げて左に同じ色の線を付ける。サイドメニューを隠しているときのツールバーでは、ラベルを出し、その右にグループのタブを並べて、タブの下に同じ色の線を付ける
- 名前を付けていないグループは「グループ N」と出す（N はグループの番号。タブの「ターミナル N」と同じ考え方）
- ラベルを押しても何もしない（折りたたみは作らない）

### 操作

- タブの右クリックのメニュー: 「新しいグループに追加」、ほかのグループごとに「グループ「名前」に追加」（色の見本付き）、グループに入っているタブでは「グループから外す」を、「上へ移す・下へ移す（左へ・右へ）」と「名前を変更…」の間に出す
  - 新しいグループに入れると、そのグループが届いたときに、ラベルの場所に名前の入力欄（「グループの名前」）を出す（Chrome と同じ）。空のまま決めると「グループ N」のまま。入力欄はタブの名前と同じもの（Enter か離れたときに決め、Esc でやめる）
  - 既存のグループに加えると、グループの最後に並ぶ。グループから外すと、グループのすぐ後ろに出る
- ラベルの右クリックのメニュー: 「名前を変更…」、8 色（選んでいる色に印。読み上げでは menuitemradio の選択状態）、「グループを解除」（タブはその場に残る）、「グループのタブを閉じる」。ラベルのダブルクリックでも名前を変えられる
  - すべてのタブが 1 つのグループに入っているときは、「グループのタブを閉じる」を選べなくする（最後のタブは閉じない、という #100 の規則のため）
- ドラッグ（docs/adr/139-tab-order.md のドラッグを広げる）
  - タブを、ほかのタブの前半・後半に重ねると、その前・後ろへ移し、重ねたタブと同じグループに入る。グループに入っていないタブに重ねると、グループから外れる
  - タブを、ラベルの前半に重ねるとグループの前（グループの外）、後半に重ねるとグループの先頭に入る。グループが並びの最後にあるときは、グループの外の最後へはドラッグで移せないので、「グループから外す」を使う
  - ラベルをドラッグすると、グループのタブをまとめて移す。グループは入れ子にできないので、ほかのグループのタブ・ラベルに重ねたときは、そのグループの前・後ろに移し、線もそのグループの前（ラベル）・後ろ（最後のタブ）に出す
- 前・後ろへ移す（右クリックのメニュー、タブにキー入力しているときの Alt+矢印。どちらも #139 のもの）
  - グループの中では、隣のタブと入れ替える
  - グループの端のタブを外へ移すと、その場でグループから外れる。端のタブも外へは移せるので、その向きの項目は選べる
  - グループの外のタブをグループの方へ移すと、グループを飛び越える。グループに入れるのは、メニューかドラッグで行う
- 新しいキーボードショートカットは作らない

### 共有と保存

- グループはサーバーが持ち、全員で共有する。`tabs` の配信に、各タブの `group`（入っているグループの ID）と、`groups`（`{ id, name, custom?, color }` の並び。タブの並びの中で現れる順）を足す
- グループのタブは、タブの並びの中で必ず続けて並ぶ。サーバーは並びやグループを変えるたびに整え、グループの途中に別のタブが入ったときは、グループの最初のタブの位置にグループのタブをまとめる（途中に入ったタブはグループの後ろに出る）。タブのなくなったグループは消す（グループのタブをすべて閉じたとき、外したときなど）
- 保存ファイル（session-store の version 2）に `groups`（`{ id, name?, color, tabs }` の並び）を足す。前の版のファイルにはないので、ないときはグループなしで戻す。読むときは、ID・色を確かめ、名前は届いたときと同じく整え直し、並びにないタブ・ほかのグループにすでに入っているタブを除き、タブのないグループを捨てる。グループの番号は、戻したグループの続きから振る
- グループを変えても、参加者ごとの表示とペアプロモードの追従は変えない（並べ替え・名前と同じ）

### 並べて表示との関係

- グループは一覧の見た目で、参加者ごとの表示（並べて表示）とは別のもの。グループのタブを並べて表示しても、グループの外のタブと並べてもよい
- 「グループのタブを閉じる」は、タブを 1 つずつ閉じるのと同じ（それぞれの参加者の表示から外し、表示するものがなくなった参加者には隣のタブを出す）
- 次・前のタブへ移るショートカット（⌘⇧. / ,）は、これまでどおりタブの並びに従う

### 色

- 青・赤・黄・緑・ピンク・紫・水色・灰色の 8 色（Chrome のタブグループと同じ数）。サーバーとは名前（`blue` など）でやりとりし、どの色で出すかはブラウザが決める
- 新しいグループには、ほかのグループが使っていない色を、この順に割り当てる。すべて使っていれば順に繰り返す
- タブの一覧（サイドメニュー・ツールバー）は、ターミナルの配色（ダーク・ライト。docs/adr/36-appearance.md）にかかわらず暗い背景なので、暗い背景の上で互いに見分けやすい明るめの色（Chrome のダークモードのタブグループの色）にし、ラベルの文字は暗い色にする。ラベルは色の地の上に文字を載せるので、背景の明暗によらず読める

### サーバー

- ブラウザから送るメッセージを足す。どれも `tab`・`group` が文字列のものだけを受け付け、ないタブ・グループへのものは無視する
  - `new-group { tab }`、`add-to-group { tab, group }`、`remove-from-group { tab }`
  - `move-group { group, index }`: グループのタブを除いた並びの `index` 番目へ移す。`index` は 0 以上、グループのタブを除いた数以下の整数
  - `rename-group { group, name }`: タブの名前と同じ `sanitizeName` で整え、空なら「グループ N」に戻す
  - `recolor-group { group, color }`: 決まった 8 色の名前だけを受け付ける
  - `ungroup { group }`、`close-group { group }`（すべてのタブが入っているグループは閉じない）
- `move-tab` に `group` を足す。文字列ならそのグループに入れ、`null` なら外し、なければこれまでどおりグループを変えない。文字列・`null` 以外のものが付いたメッセージは、全体を無視する

## 理由

- 1: 並び順・タブの名前と同じく、「app のグループ」のように一緒に作業する人どうしで同じものを指せるほうが役に立つ。サーバーが持てば、保存と復元も並び・名前と同じ仕組みで済む
- 2: ラベルの右にグループのタブを並べる見た目（Chrome）は、続けて並んでいることが前提。続けて並べておけば、グループの位置と並びを別に持つ必要がない
- 3: 重ねた場所の周りと同じグループになる、という 1 つの規則で、入れる・外す・移すがドラッグだけで済む。B は、境目に見分けにくい落とし先が 2 つ並ぶ
- 4: 端で外れる・飛び越えるにすると、何度か押せばどこへでも移せ、グループに意図せず入ることがない。グループに入れる操作はメニューとドラッグにあり、目で見て選べる
- 5: グループに表示の意味を持たせると、グループごとに「どう並べるか」を決める必要が出て、並べられる数（3 つ）とも合わない。一覧の見た目にとどめれば、#100・#163 の表示の仕組みを変えずに済む
- 6: 決まった色なら、どの参加者の画面でも同じ色名で呼べ、見分けにくい色や読めない組み合わせを選ばずに済む。サーバーは名前だけを確かめればよい
- 7: 今の右クリックのメニュー（context-menu.ts）は入れ子を持たない。グループの数はふつう少ないので、項目を並べても長くなりすぎない
- 8: 並べ替え（#139）と同じく、操作を送ればサーバーは今あるタブ・グループかを確かめるだけで済み、ほかの参加者の同時の操作で知らないタブを消したり戻したりしない

## 影響・今後の課題

- ほかの参加者がグループを変えると、自分の一覧も変わる。ドラッグしている間と名前を付けている間は、終わるまで変わらない（#139・#110 と同じ）
- 同時に操作したときは、サーバーに後から届いたものが勝つ
- グループが並びの最後にあるときは、ドラッグでグループの外の最後へは移せない（メニューの「グループから外す」か「下へ移す」で外す）
- グループが多いと、タブの右クリックのメニューが長くなる

## 含めないもの

- グループの折りたたみ
- グループのキーボードショートカット
- ターミナルのバーや、ターミナルの右クリックのメニューにグループを出すこと
- グループの名前の重なりを見分けるための番号（タブの名前と違い、ラベルに入力させる先はないので、偽装の心配が小さい）
