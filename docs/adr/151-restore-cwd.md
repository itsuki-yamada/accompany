# 開き直したときに、各タブで作業していたディレクトリでシェルを始める

- 日付: 2026-10-23
- ストーリー: #151

## 背景

Accompany を止めて開き直すと（[ADR 34](34-session-restore.md)）、タブとスクロールバックは戻るが、各タブのシェルは Accompany を起動したディレクトリで始まっていた。止める前に作業していたディレクトリで続けたい。

作業していたディレクトリを調べる仕組みは、分割や新しいタブのために [ADR 109](109-inherit-cwd.md) で入れた（前面のプロセスグループのリーダーのカレントディレクトリ、なければシェル自身。ps と lsof、Linux は `/proc`）。次の点で判断が要った。

1. 保存のたびに ps・lsof を動かす費用。変化のたびの保存は 1 秒おきに起きうる
2. 起動時のコマンドを動かしていたタブを、どのディレクトリで動かすか
3. 古い保存ファイルとの互換
4. 保存したディレクトリがなくなっていたとき

## 検討した案（いつ・どうやってディレクトリを知るか）

- **A**: ADR 109 の方法（ps・lsof）で調べる。止めるときは全部のタブを、変化のたびの保存では前に調べてから入力があったタブだけを調べ直す
- **B**: 止めるときだけ調べる。軽いが、止める操作を経ずに落ちたとき（強制終了、マシンが落ちた）はディレクトリを失う
- **C**: シェルが出す OSC 7（カレントディレクトリを知らせるエスケープシーケンス）だけを使う。ps・lsof が要らず正確だが、macOS の既定の zsh や bash は出さない（設定が要る）ので、多くの利用者に効かない。出力の中のシーケンスなので、cat したファイルや ssh 先のシェルが出したものも受け取ってしまう
- **D**: C を基本にし、OSC 7 を出さないシェルを A で補う。正確で軽いが、ディレクトリを知る経路が 2 つになり、どちらを信じるかの判断も要って複雑になる

A を選ぶ。設定なしで誰にでも効き、#109 の調べ方と同じ結果になる（分割したときと開き直したときで、始まるディレクトリが食い違わない）。強制終了しても、変化のたびの保存で少し前のディレクトリが残る。費用は、入力があったタブに限ることで抑えられる。D は将来の改善とする（ps・lsof の費用が問題になったときや、OSC 7 を出すシェルが増えたとき）。

## 決定

- **保存するもの**: ターミナルごとに、ADR 109 と同じ方法で調べたカレントディレクトリ（`terminals.<id>.cwd`）を保存する。前面で別のディレクトリのコマンドが動いていれば、そのディレクトリになる。保存ファイルの形式は version 2 のまま、項目を足すだけにする
- **いつ調べるか**:
  - 止めるときの保存では、すべてのターミナルを必ず調べ直す。ただし調べるのは 1.5 秒までにし、間に合わなければ前に調べたものを使う。保存全体を待つ上限（3 秒）の中で、画面の書き出しと書き込みの時間を残すため
  - 変化のたびの保存では、前に調べてから入力があったターミナルだけを調べ直し、ほかは前に調べたものを使う。ただし、前に調べたときと同じエージェント（[ADR 70](70-agent-detection.md) の判定）が前面にいる間は、入力があっても調べ直さない。エージェントが終わって前面が替われば、調べ直す
  - Enter を押してからシェルが cd し終えるまでの間に調べると、前のディレクトリが返る。調べ始める 200 ミリ秒前までに入力があったときは、調べたあとも調べ直すべきものとして残す
  - まだシェルを起動していない（誰もそのタブを開いていない）ターミナルは、調べずに起動する予定のディレクトリを保存する
- **調べられなかったとき**: 前に調べたもの（なければ起動する予定のディレクトリ）を使う。どれもなければ保存しない
- **起動時のコマンドを動かしていたタブ**: 起動時のコマンドを指定して起動したとき（`accompany -- <コマンド>`）は、そのコマンドは Accompany を起動したディレクトリで動かす。起動時のコマンドを省略したとき（`$SHELL`）は、ほかのタブと同じく保存したディレクトリでシェルを始める
- **なくなっていたとき**: ADR 109 と同じく、`Bun.spawn` が失敗したら Accompany を起動したディレクトリで起動し直す
- **古い保存ファイル**: `cwd` を持たないターミナルは、これまでどおり Accompany を起動したディレクトリで始める。`cwd` が絶対パスの文字列でなければ、ないものとして扱う
- **パーミッション**: ディレクトリのパスも、スクロールバックと同じファイル（0600、ディレクトリは 0700）に入れる

## 理由

- **入力があったときだけ調べ直す理由**: シェルのカレントディレクトリが変わるのは、ほとんど cd などを入力したときなので、出力が続くだけのターミナル（ビルドやエージェントの出力）で 1 秒ごとに ps と lsof を動かさずに済む。macOS の lsof は 1 回に数十ミリ秒かかり、タブの数だけ動く。入力のあとの調べ直しは、変化のたびの保存の間隔（1 秒）より多くは起きない
- **エージェントが前面の間は調べ直さない理由**: エージェントへの指示は入力として届くので、そのたびに ps と lsof が動いてしまう。エージェント自身はふつう作業するディレクトリを変えない（変えても、保存するのはエージェントのプロセスのディレクトリ）
- **止めるときは必ず調べる理由**: 入力なしに前面のコマンドが終わる（ビルドが終わってシェルに戻る）と、前に調べたディレクトリと今のディレクトリが違うことがある。止めるのは 1 回だけなので、費用は問題にならない
- **調べる時間に上限を付ける理由**: ps と lsof にはそれぞれ 2 秒の上限があり、続けて動くと 3 秒を超えうる。止めるときの保存が 3 秒を超えると、何も保存されないまま止まってしまう
- **起動時のコマンドを起動したディレクトリで動かす理由**: `accompany -- claude` のように、起動時のコマンドは起動したディレクトリ（プロジェクトのルート）で動くことを前提に指定されている。エージェントの会話や設定はディレクトリごとに分かれることが多く、別のディレクトリで動くと、起動のたびに違うものとして始まってしまう。起動時のコマンドを省略したときはただのシェルなので、ほかのタブと分ける理由がない
- **version を上げない理由**: 項目を足すだけで、前の版のファイルも、項目がないものとしてそのまま読める。前の版の Accompany で新しいファイルを読んでも、知らない項目は無視される

## 影響・今後の課題

- 入力なしにカレントディレクトリが変わったとき（前面のコマンドが終わった、スクリプトが cd した）は、止める操作を経ずに落ちると、前に調べたディレクトリで始まる
- 止めるときに調べる分だけ、止まるのが遅くなる（通常は数十ミリ秒、最長で 1.5 秒）
- 保存したディレクトリが消えていても、警告は出さずに起動したディレクトリで始める
- 起動時のコマンドを動かしていたタブを閉じていて、新しいタブで起動時のコマンドを動かすとき（ADR 34）も、起動したディレクトリで動かす
- ADR 109 の「再起動で戻したターミナルは、起動したディレクトリで始める」は、この ADR で置き換わる
- `SHELL` が相対パスのときは、ADR 109 と同じく、保存したディレクトリではシェルが見つからず、起動したディレクトリで起動し直す

## 含めないもの

- 前面で動いていたコマンドの再実行（ADR 34 のとおり、プロセスは戻さない）
- シェルの環境変数や履歴の復元
