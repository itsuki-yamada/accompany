# ターミナル 1 つをタブ 1 つにし、表示するタブと分割は参加者ごとに選ぶ

- 日付: 2026-10-22
- ストーリー: #100
- docs/adr/21-tabs.md（タブ＝Workspace が分割の配置を持ち、表示中のタブを全員で共有する）を置き換える

## 背景

いまは「Workspace」（コード上の tab）の中に「分割したペイン」があり、ブラウザの道具にしては概念が多い。表示中の Workspace と分割の配置は参加者全員で共有している。v0.10.0 を使ってのフィードバックに、次のものがあった。

- ペアプロモードをやめても、相手に合わせて Workspace が切り替わってしまう（表示中の Workspace を全員で共有しているため）
- 分割したものから独立させたい

ユーザーとの相談で、次のことが決まった（Issue #100 の本文とコメント）。

- ターミナル 1 つを、タブ 1 つとして扱う。Workspace という入れ物はなくす
- タブを 1 つ選べば、そのターミナルだけが画面いっぱいに出る。タブを複数選ぶと、選んだものが分割して並ぶ。分割はあくまでオプションで、すぐに 1 つの表示に戻せる（Chrome の画面分割に近い）。並べられるのはまず 3 つまで
- どのタブを選んで見ているかは参加者ごと。ペアプロモード（#93）の間は、相手のタブの選び方と分割もそのまま追従し、完全に同じ画面を見る
- これまでの Workspace と分割の配置（保存したものを含む）は引き継がなくてよい
- 最大化（#97）は作らない（タブを 1 つ選べば画面いっぱい）。自動の拡大は #126 で消した

このほかに、次のことを決める必要があった。

1. サーバーが持つものと、参加者ごとの選択・分割の割合の置き場所
2. ペアプロモードの追従のしかた
3. タブを複数選ぶ操作と、1 つの表示に戻す操作
4. サイドメニュー（#72・#76）の一覧と件数・未確認（#74）・状態の表示、ツールバー
5. 新しいタブ・分割の作業ディレクトリ（#109・#118）
6. ショートカットの読み替え
7. 保存と復元（session-store の形の変更と古い形の扱い）
8. 端末の大きさ（#99・#103）と、分割して枠が下限より狭くなるときの扱い

## 検討した選択肢

### 1. 参加者ごとの表示（どのタブを選んでいるか・分割の配置と割合）の置き場所

- A. 各ブラウザだけに持つ。サーバーはタブの一覧だけを持つ
- B. サーバーが参加者ごとに持ち、その参加者にだけ配る

### 分割の形

- A. 選んだタブを一方向（左右）に並べるだけ
- B. これまでと同じ分割の木（左右・上下の入れ子）を、参加者ごとに持つ。葉は 3 つまで

### 2. ペアプロモードの追従

- A. 追従している側のブラウザが、相手の表示を受け取って描く（自分の表示は変えない）
- B. サーバーが、相手の表示を追従している側の表示に写す（相手の表示が変わるたびに写し直す）

### 3. タブを選ぶ操作

- A. タブを選ぶと、そのタブだけを表示する。⌘ / Ctrl を押しながら選ぶか「並べて表示」のボタンで、選んでいるタブに加える・外す（ファイルの選択と同じ）
- B. 分割に入っているタブを選んだときは、分割のままそのタブにフォーカスする（Chrome の画面分割と同じ）。1 つの表示に戻すには別の操作を使う

## 決定

### サーバーが持つもの（1 は B、分割の形は B）

- サーバー（`Workspace`）は、タブ（ターミナル）の一覧と並び順を持ち、`{ type: "tabs", tabs: [{ id, name }] }` で全員に配る。名前は「ターミナル N」。コマンドが設定したタイトルは、これまでどおり `titles` で配る。並び順は開いた順で、新しいタブ・分割で開いたタブは最後に足す
- 参加者ごとの表示（分割の木。葉がタブ、節が向きと割合）をサーバーが持ち、`{ type: "view", layout }` でその参加者にだけ配る。葉は 3 つまで（`maxPanes`）
- 参加したときの表示は、起動時のコマンドを動かしているタブ（閉じていれば最初のタブ）1 つ
- ブラウザから送るメッセージ
  - 表示を変える（その参加者の表示だけが変わる）: `new-tab { terminal? }`（新しいタブを開いて、それだけを表示する）、`select-tab { tab }`（そのタブだけを表示する）、`split { terminal, direction }`（新しいタブを開いて、そのターミナルの右・下に並べる）、`add-to-view { tab, terminal? }`（開いているタブを、terminal の右に並べる。terminal を表示していなければ全体の右）、`remove-from-view { tab }`（並べているタブを外す）、`resize-split { split, ratio }`（割合を変える）
  - 全員に効く: `close { terminal }`（タブを閉じ、ターミナルを終了する）
- `close-tab` はなくした（タブとターミナルが同じになったので `close` だけにする）
- タブを閉じると、そのタブを表示していた参加者の表示から外す。表示するものがなくなった参加者には、閉じたタブの右隣（なければ左隣）のタブを出す。最後のタブは閉じられない。シェルが終了したときも同じ
- 未確認（#74）を消す「見ている」は、その参加者が自分の表示にあるタブにフォーカスしていて、ページが見えていること

### ペアプロモード（2 は B）

- ペアプロモードを始めたとき、サーバーは相手の表示（分割の木と割合）を、追従している側の表示に写して配る。相手の表示が変わるたびに写し直す。追従の連鎖（A が B に、B が C に追従）も順に写し、輪（A と B が互いに追従）でも止まる
- 追従している人が自分で表示を変えたら（タブを選ぶ・並べる・外す・新しいタブ・分割・割合の変更）、ペアプロモードをやめる。ブラウザがやめたことを先に送り、サーバーも表示を変える操作を受けたらやめたものとする
- ペアプロモードをやめても、表示はやめたときのまま（相手に合わせていた表示）にする。そのあと相手がタブを切り替えても、自分の表示は変わらない
- フォーカスとスクロールの追従、自分の操作でやめる条件は、docs/adr/93-pair-mode.md のまま

### タブを選ぶ操作（3 は A）

- サイドメニュー（とツールバー）のタブを選ぶと、そのタブだけを画面いっぱいに出し、そのターミナルにフォーカスする。分割して並べているときも、タブを 1 つ選べば 1 つの表示に戻る
- ⌘ / Ctrl を押しながらタブを選ぶか、サイドメニューの各タブの「並べて表示」（⊞、`aria-pressed`）を押すと、選んでいるタブに加える（フォーカスしているターミナルの右に並べ、そこにフォーカスする）。並べているタブで押すと外す。表示しているタブが 1 つのときは外せず、3 つ並べているときはそれ以上加えられない（ボタンを押せなくする）
- ターミナルのバーの「右に分割」「下に分割」は、新しいタブを開いて、そのターミナルの右・下に並べる。3 つ並べているときは押せない（右クリックメニューも同じ）
- 境界のドラッグで変わる割合は、自分の表示だけに効く

### サイドメニューとツールバー

- サイドメニューは、Workspace の一覧とセッションの一覧を 1 つにまとめ、「タブ」の一覧にする（`role="tablist"`、`aria-multiselectable`）。各行に、タブ（状態・「ターミナル N」・タイトル・フォーカスしている参加者）、並べて表示、閉じるのボタンを並べる。表示しているタブは `aria-selected`
- 見出しに、全タブの状態の件数（作業中・未確認・指示待ち。0 件は出さない）と、新しいタブの「+」を置く。Workspace ごとの件数はなくした（タブ 1 つにつき状態は 1 つなので、行の印で分かる）
- 並び順は状態で入れ替えない（docs/adr/72-sidebar.md のまま）
- ツールバーには、サイドメニューを隠している間だけ、タブの一覧を横に並べる（選ぶ・⌘ / Ctrl を押しながら選ぶ・新しいタブ）。サイドメニューを出しているときは同じ一覧が二重にならないよう出さない。これまでの「表示中の Workspace の名前」はなくした
- キーボード: ⌘⇧E でサイドメニューの、自分がフォーカスしているターミナルの行へ移る。↑↓ で行を移り、Enter で選ぶ（そのタブだけを表示してフォーカスする）、Esc でターミナルに戻る。Workspace を選んだときにサイドメニューに残す動き（#72）は、Workspace がなくなったのでなくした
- 画面の表記の「Workspace」はなくし、「タブ」にする

### 新しいタブの作業ディレクトリ（#109・#118）

- これまでと同じ。⌘⇧O・⌘⇧R / D・バーの分割のボタンは、キー入力の先（ボタンのターミナル）の、サイドメニューとツールバーの「+」は自分が最後にフォーカスしたターミナルのカレントディレクトリで始める

### ショートカット

| キー | これまで | これから |
|---|---|---|
| ⌘⇧O | 新しい Workspace | 新しいタブ（それだけを表示する） |
| ⌘⇧R / D | 右・下に分割 | 新しいタブを開いて右・下に並べる。3 つ並べていれば何もしない |
| ⌘⇧X | ターミナルを閉じる | タブ（ターミナル）を閉じる |
| ⌘⇧矢印 | 隣のターミナルへ移る | 並べているタブの隣へ移る（同じ） |
| ⌘⇧. / , | 次・前の Workspace | キー入力の先のタブの次・前のタブだけを表示する（端では反対側に回る） |
| ⌘⇧E / S | サイドメニュー | 同じ |

### 保存と復元

- 保存ファイルの形を `version: 2` にする: `{ version: 2, cwd, tabs: string[]（タブの並び）, terminals, commands, minWindow? }`。参加者ごとの表示は保存しない（参加者は接続ごとなので、開き直すと最初の表示に戻る）
- `version: 1`（Workspace と分割の配置）のファイルは、Workspace の順・配置の順にターミナルを並べてタブとして戻し、分割の配置と表示中の Workspace は捨てる。スクロールバック・よく使うコマンド・下限は戻す。形が正しくなければ、これまでどおり新しく始める

### 端末の大きさ

- これまでどおり（docs/adr/99-smallest-size.md）。端末の大きさは、そのターミナルにつながっている（自分の表示に入れている）参加者のうち一番小さい表示領域に合わせ、下限まで広げる。下限は「ターミナル 1 つがウィンドウを占めるとき」の大きさとしてペインごとに伝える
- 分割して枠が下限より狭くなった参加者は、はみ出した分をスクロールか縮小（表示の設定）で見る（docs/adr/126-no-zoom.md）。分割で下限を割ると、そのタブを 1 つで見ているほかの参加者の端末まで細くなるため
- どの参加者も表示していないタブのターミナルは、最後の大きさのまま動き続ける

## 理由

- 表示をサーバーが持つ（1 の B）: ペアプロモードで相手の表示に追従するにはサーバーが相手の表示を知っている必要があり、未確認（#74）を消すには、誰がどのタブを表示しているかが要る。新しいタブ・分割は、ターミナルを作ることと自分の表示に入れることを 1 つの操作で行えるので、作ったターミナルがどの参加者の頼んだものかをブラウザで突き合わせずに済む。表示は本人にだけ配るので、ほかの参加者の通信は増えない
- 分割の木を残す（分割の形の B）: これまでの「右に分割」「下に分割」と境界のドラッグ、組み立て（`build`）や隣への移動の処理をそのまま使える。3 つまでなら木でも複雑にならない
- サーバーが写す（2 の B）: 追従している側の表示を相手の表示そのものにすれば、ブラウザは自分の表示を描くだけでよく、未確認の判定や大きさの計算（つながっている参加者）もふだんと同じになる。やめたときに表示が飛ばない（相手に合わせていた表示のまま残る）
- 自分で表示を変えたらペアプロモードをやめる: 写し続けると、自分で選んだ表示が相手の表示で上書きされる。「相手と別のターミナルを操作したらやめる」（docs/adr/69-follow.md）と同じ考え方
- タブを選ぶと 1 つにする（3 の A）: ユーザーの言う「タブを 1 つ選べば画面いっぱい、複数選べば分割」がそのまま操作になり、1 つの表示に戻すのもタブを選ぶだけで済む。B は Chrome に近いが、1 つの表示に戻す別の操作が要り、分割しているかどうかで同じ操作の結果が変わる
- ツールバーにはサイドメニューを隠している間だけタブを出す: 隠していてもタブを選べる必要がある。二重に出すと、同じタブがどちらにもあり、どちらを使えばよいか迷う
- 古い保存ファイルからターミナルを戻す: 「忘れてよい」のは配置で、スクロールバックやよく使うコマンドまで捨てると、更新しただけで画面が消えたように見える。並べ直すのは数行で済む

## 関係する ADR

- docs/adr/68-zoom.md・docs/adr/126-no-zoom.md: 自動の拡大はない（126 のまま）。1 つのターミナルを画面いっぱいに見るには、そのタブだけを選ぶ。最大化（#97）は作らない

- docs/adr/72-sidebar.md: 「タブ」を「Workspace」と呼ぶこと、Workspace の一覧とセッションの一覧を分けることを置き換える。出す・隠すの扱い、並び順、⌘⇧E・⌘⇧S は残す。「表示中の Workspace は全員で共有しているので、セッションの一覧から移るとほかの参加者の表示も切り替わる」は解消する
- docs/adr/74-unseen-done.md: 「見ている」の「表示中の Workspace にある」を「自分の表示にある」に読み替える
- docs/adr/99-smallest-size.md: 変えない。分割して下限を割ったときは、スクロールか縮小で見る
- docs/adr/109-inherit-cwd.md: 変えない
- docs/adr/34-session-restore.md: 保存ファイルの形を変える（上の「保存と復元」）

## 影響・今後の課題

- ほかの参加者がタブを開いても、自分の表示は変わらない。新しいタブは一覧の最後に出る
- タブを選び直すと、それまでの分割の配置と割合は残らない（Chrome のように分割したタブの組を覚えておくことはしない）
- 開き直す（再読み込み）と、表示は最初のタブ 1 つに戻る
- ターミナルのバーが狭い枠に収まらないこと（docs/adr/72-sidebar.md）は、3 つまでに限ったので起きにくくなったが、残る

## 含めないもの

- タブの並び替え（ドラッグ）、タブの名前を変えること
- 4 つ以上並べること
- 参加者ごとの表示を保存して、開き直したときに戻すこと
- 最大化（#97）
