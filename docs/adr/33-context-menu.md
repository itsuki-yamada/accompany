# ターミナルの右クリックメニューと、ターミナルのリセット

- 日付: 2026-10-15
- ストーリー: #33

## 背景

ターミナルを右クリックしたときに、Accompany 独自のメニュー（コピー・ペースト・すべて選択・ターミナルのリセット・分割）を出す。次の 3 点で判断が要った。

1. **リセットの範囲**: Accompany では、参加者全員が同じ PTY の出力を見ていて、サーバー側にも `@xterm/headless` の画面がある（途中から参加した人に画面を復元するため）。マウスの報告モードやブラケットペーストなどのモードは、出力に含まれるエスケープシーケンスで切り替わる「画面の状態」なので、参加者全員の画面とサーバー側の画面が同じ状態を持っている。復元に使う `SerializeAddon` は、マウスの報告モードなども書き出す
2. **マウスの報告モードとの関係**: TUI がマウスの報告モードを有効にしていると、xterm.js は右クリックをアプリに報告する。リセットが一番要るのは、TUI が異常終了してマウスの報告モードが残ったときで、そのときにメニューが出ないと困る
3. **クリップボードの権限**: コピー（`navigator.clipboard.writeText`）は、クリックなどの操作の中であれば Chrome では許可なしで使える。ペースト（`readText`）は、ブラウザが利用者に許可を求め、拒否されることがある

## 検討した選択肢

### リセットの範囲

1. 自分のブラウザの画面だけをリセットする（`terminal.reset()`）
2. サーバーに伝え、サーバーが自分の画面と参加者全員の画面に RIS（`ESC c`、xterm の完全なリセット）を流す
3. 2 に加えて、コマンドに Ctrl+L などを送って再描画させる

### マウスの報告モードのときの右クリック

1. アプリに渡す（xterm.js の既定）。Shift+右クリックでメニューを出す
2. 常にメニューを出し、右クリックはアプリに渡さない

### ペーストの権限がないとき

1. 何もしない
2. ターミナルの中に、キーボードでのペースト（Cmd+V / Ctrl+V）を案内するメッセージを出す

## 決定

- リセットは 2 を採る。ブラウザはターミナルの WebSocket で `{ type: "reset" }` を送り、サーバーは自分の画面に `ESC c` を書き込み、同じものを出力として全員に配る。コマンドには何も送らず、シェルも再起動しない
- リセット（RIS）では、コマンドが OSC 0 / 2 で設定したタイトル（#32）も消す。xterm.js は RIS でタイトルの変更を知らせないので、サーバー側の画面で RIS を見たときに自分でタイトルを空にし、全員に配る
- 右クリックは 2 を採る。マウスの報告モードかどうかにかかわらず、右クリックはアプリに渡さずにメニューを出す
- ペーストの権限がないときは 2 を採る。ターミナルの下に `role="alert"` でメッセージを出し、数秒で消す

## 理由

- リセット: モードは参加者全員とサーバー側の画面が共有している状態なので、自分の画面だけを戻すと、ほかの参加者の画面にはモードが残り、途中から参加した人にも `SerializeAddon` がモードを復元してしまう。リセットを出力の流れに混ぜて配れば、PTY の出力と同じ順番で全員とサーバー側の画面に届き、新しいメッセージの種類もブラウザ側に増やさずに済む（ブラウザは出力として処理するだけ）。参加者全員で同じ画面を共有する方針にも合う
- タイトルを消すのは、異常終了した TUI が残したタイトルも、モードと同じく「リセットで戻したい状態」だから。タイトルは端末の状態なので、xterm の RIS（`reset` コマンド）を受けた端末の多くと同じく初期状態に戻す。シェルがプロンプトのたびにタイトルを設定していれば、次のプロンプトでまた出る
- リセットでコマンドに入力を送らないのは、動いているコマンドが何かによって入力の意味が変わり、予期しない動作を起こしうるため
- 右クリック: TUI が右クリックを使う場面は少ない。一方で、マウスの報告モードが残ってしまったときこそリセットのメニューが要るので、常にメニューが出る方が分かりやすい。Shift+右クリックは知らないと使えない
- ペースト: 何もしないと、押しても反応しない理由が分からない。キーボードでのペーストは xterm.js の paste イベントで権限なしに使える

## 影響・今後の課題

- リセット（RIS）は、画面とスクロールバックも消す（xterm の `reset` コマンドと同じ）。押した人だけでなく、参加者全員の画面が消える。シェルのプロンプトは、Enter を押すと出る
- RIS は PTY の出力の途中（エスケープシーケンスの途中など）に挟まることがありうる。その場合でも、RIS が解析中のシーケンスを打ち切るだけで、リセット後の状態は変わらない
- TUI に右クリックを渡す手段はない。必要になったら、Shift+右クリックでアプリに渡すなどを検討する
- メニューは右クリック（とキーボードのコンテキストメニューキー）で開く。ほかの場所（バーやタブ）のメニューは扱わない
