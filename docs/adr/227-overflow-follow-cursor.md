# はみ出したターミナルでは、枠のスクロールでカーソルの行（最新の出力）を追う

- 日付: 2026-11-02
- ストーリー: #227
- docs/adr/116-overflow-scroll-bottom.md の「枠のスクロールを一番下に保つ」を、「カーソルの行を追う」に広げる。表示し直したとき・大きさが変わったときに一番下へスクロールすることは、引き続き 116 による

## 背景

利用者から「`git add -p` などを打つと、共有している相手の画面で最新の出力が見えないことがあった」と報告があった。

端末が自分の表示領域より大きい参加者（docs/adr/99-smallest-size.md の下限より画面の低い人など）は、はみ出した部分をペインの枠（`.pane-terminal`）のスクロールで見る。#116 で、枠を一番下に保つのは、表示し直したとき（最初の出力を書き終えたとき）と、枠・端末の大きさが変わったときだけにした。出力が来ても枠は動かない。

本物の `git add -p` とホスト・ゲストの 2 つのブラウザで確かめると、画面がいっぱいでないとき（`clear` の直後、開いたばかりのシェルなど）に、次の 2 つが起きた。

- 画面の小さい人がコマンドを打つと、ブラウザが入力欄（xterm はカーソルの位置に置く）を見せるために枠を上のほうへスクロールする。枠が一番下でなくなるので、一番下に保つのが外れる。そのあと diff が下まで流れても枠は上のほうで止まり、`Stage this hunk ...?` の問い合わせが見えない
- 画面の大きい人が短い出力のコマンドを打つと、画面の小さい人の枠は一番下（空の行）を見せたままで、上のほうに出た出力と問い合わせが見えない

どちらも、最新の出力が出る位置（カーソルの行）は端末の一番下とは限らないのに、枠が一番下だけを基準にしていることによる。

画面の大きさが同じ・ゲストのほうが大きい、縮小表示、フォントの大きさの違い、deviceScaleFactor 2、ペアプロモードの追従、スクロールバックの上限を超える出力、ゲストのホイール操作では起きなかった。

## 検討した選択肢

1. 出力のたびに、枠を一番下までスクロールする（一番下に保っているとき）
2. 出力のたびに、カーソルの行が枠の外に出ていれば、カーソルの行が見えるところまでスクロールする（追っているとき）
3. 文字を打ったときのブラウザのスクロールを止める（入力欄のフォーカスやスクロールを抑える）

## 決定

- 選択肢 2。枠のスクロールで「最新の出力を追うか」を持つ（#116 の「一番下に保つか」を置き換える）。作ったときは追う
- 追っているとき、出力を書き終えるたび（xterm の `onWriteParsed`）に、カーソルの行が枠の見えている範囲の外にあれば、カーソルの行が枠の一番下に来るようにスクロールする。カーソルが上にあるときも一番下に合わせ、カーソルより上に出た出力をなるべく多く見せる
- 表示し直したとき・大きさが変わったときは、これまでどおり一番下までスクロールし、カーソルの行がそれより上にあれば、カーソルの行まで戻す
- 枠のスクロール位置が、最後に自分で動かした位置から変わっていたら（参加者のスクロール、文字を打ったときのブラウザのスクロールなど）、その位置で追うかを決め直す。枠が一番下にあるか、カーソルの行が見えていれば追い、どちらでもなければ追わない
- 決め直しは、スクロールのイベントに加えて、出力でスクロールする直前にも行う。スクロールのイベントは次の描画の前まで届かないので、その間に出力が届くと、自分で上へスクロールしたのに引き戻してしまうため
- 端末がはみ出していないとき、xterm のスクロールバック（枠ではなく xterm の中のスクロール）を見ていてカーソルが xterm の表示の外にあるときは、何もしない

## 理由

- 選択肢 1 では、画面がいっぱいでないときの出力（2 つ目の例）が見えないまま残る。最新の出力の位置はカーソルの行なので、カーソルの行を基準にする
- 選択肢 3 は、ブラウザの入力欄の扱いや IME と絡み（入力欄は変換中の文字を出す位置でもある）、壊れても気づきにくい。ブラウザのスクロールはそのままにし、カーソルの行が見えているので追い続ける、と扱うほうが単純
- 文字を打ったときのブラウザのスクロールは、カーソルの行を見せるものなので、そのあとも追う。自分で上にスクロールしてカーソルの行を見えなくしたときだけ追わない（読んでいる位置を奪わない、#116 と同じ考え）
- カーソルの行を一番下に合わせる: 端末と同じく、最新の行を下に、それまでの出力を上に見せる

## 影響

- 画面がいっぱいでないとき、はみ出した枠は一番下ではなく、カーソルの行が一番下に来る位置で止まることがある（それより下は空の行）
- フルスクリーンの TUI（エディタなど）でカーソルを動かすと、カーソルが枠の外に出るたびに枠がスクロールする

## 含めないもの

- 横のスクロール（左端から見せる、いまのまま）
- 縮小表示（はみ出さないので関係しない）
