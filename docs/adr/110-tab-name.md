# タブ（ターミナル）に名前を付ける

- 日付: 2026-10-23
- ストーリー: #110

## 背景

ターミナルの名前は「ターミナル N」と、コマンドが設定したタイトル（docs/adr/32-titles.md）だけで、自分では変えられない。何のためのターミナルか（app、e2e など）が分かる名前を付けたい。#100（docs/adr/100-terminal-tabs.md）でターミナル 1 つが 1 つのタブになったので、「タブの名前」として扱う。

迷ったのは、次の点。

1. 名前を全員で共有するか、参加者ごとにするか
2. 付けた名前と、コマンドが設定したタイトル・「ターミナル N」との関係
3. 付け方
4. 検証と、見分けにくい名前の扱い

## 検討した選択肢

1. 共有するか
   - A. サーバーが持ち、全員で共有する。保存する
   - B. 参加者ごとにブラウザに覚えておく
2. タイトルとの関係
   - A. 付けた名前は「ターミナル N」の代わりに出し、コマンドが設定したタイトルはこれまでどおり並べて出す
   - B. 付けた名前があるあいだは、コマンドが設定したタイトルを出さない
3. 付け方
   - A. 名前のダブルクリックと右クリックのメニューで、その場に入力欄を出す
   - B. ダイアログ（設定の画面など）で付ける
4. 検証
   - A. 参加者の名前と同じ `sanitizeName`（docs/adr/96-member-name.md）でサーバーが整え、ほかのタブと見分けにくい名前には番号を添える
   - B. ブラウザで整え、見分けにくい名前はそのまま出す

## 決定

1 は A、2 は A、3 は A、4 は A を採る。

- 名前はサーバーが持ち、全員で共有する。タブの並び（`tabs`）の各タブに、画面に出す名前（`name`）と付けた名前（`custom`。付けていなければない）を入れて配る。保存ファイル（session-store の version 2）に `names`（ターミナルの ID → 付けた名前）を足す。前の版のファイルにはないので、ないときは名前なしで戻す。読むときも、届いたときと同じく整え直す
- 付けた名前は「ターミナル N」の代わりに、ターミナルのバー、サイドメニューとツールバーのタブ（閉じる・並べて表示のボタンや右クリックのメニューの名前も）、作業が終わったときの通知（「名前: 指示待ち」）に出す。未確認などの状態は、これまでどおりタブの名前の横に出る。コマンドが設定したタイトルは、これまでどおりバーとサイドメニューに並べて出す。名前を空にすると「ターミナル N」に戻る
- ターミナルの領域（region）の読み上げ名は、名前を付けても「ターミナル N」のままにする（同じ名前のタブがあっても、どのターミナルか分かるように）
- 付け方
  - ターミナルのバーの名前、サイドメニュー・ツールバーのタブをダブルクリックすると、名前の場所に入力欄（「ターミナルの名前」）を出す
  - サイドメニュー・ツールバーのタブの右クリックのメニューと、ターミナルの右クリックのメニューに「名前を変更…」を足す。ターミナルのメニューでは「ターミナルのリセット」の前に置く（「右に分割」「下に分割」を最後に残す）
  - 入力欄には付けている名前を入れ（付けていなければ空で、例として「ターミナル N」を出す）、Enter か入力欄を離れたときに決め、Esc でやめる。Enter・Esc で閉じたら、キー入力の先をターミナル（バー・ターミナルのメニューから）やタブ（サイドメニュー・ツールバーから）に戻す
  - 名前を付けている間は、サイドメニューを組み直さない（ドラッグしている間と同じ）。表示していないタブをダブルクリックしたときは、そのタブに切り替わっても入力欄からキー入力の先を奪わない。ダブルクリックの 1 回目のクリックはふだんどおりタブを選ぶ操作なので、ペアプロモードの間に表示していないタブをダブルクリックすると、ペアプロモードは終わる
  - 入力欄は、ブラウザでも参加者の名前と同じく前後の空白を除き、32 文字（書記素）までに切り詰める
- 検証: サーバーは `{ type: "rename-tab", tab, name }` のうち、`tab` と `name` が文字列のものだけを受け付け、`name` を `sanitizeName`（参加者の名前と共用）で整える。ないタブへのものは無視する。整えて空になったもの、見えない文字だけのものは、名前を付けていないものとする
- 見分けにくい名前: 付けた名前が、ほかのタブの名前（付けた名前、または「ターミナル N」）と同じとき、またはほかの番号の「ターミナル N」と同じときは、「名前（ターミナル N）」と番号を添える。同じかは参加者の名前と同じく `nameKey`（NFKC、見えない文字・結合文字を除く）で比べ、さらに空白を無視する（「ターミナル2」「ターミナル　２」も「ターミナル 2」とみなす）。番号を添えた形（「名前（ターミナル N）」）をまねた名前にも添える。付けていないタブ（「ターミナル N」）には添えない
- 長い名前は、バー（16em）・ツールバーのタブ（12em）・サイドメニュー（幅いっぱい）で末尾を省き、全文はツールチップで見せる

## 理由

- 1: 「app」「e2e」のような名前は、一緒に作業する人どうしで同じ名前で呼べるほうが役に立つ。タブの並びと同じく、サーバーが持って保存すれば、再起動しても残る。参加者ごとにすると、ほかの人の画面ではどれが「app」か分からない
- 2: コマンドが設定したタイトル（vim のファイル名、シェルのカレントディレクトリなど）は、何が動いているかを知るのに役立つ。付けた名前は「何のためのタブか」で、別の情報なので、片方で片方を隠さない。「ターミナル N」の場所を置き換えれば、空にしたときに元の表示にそのまま戻る
- 3: その場で付けられると、名前を見ている場所から離れずに済む。ダブルクリックは見つけにくいので、右クリックのメニューにも置く（キーボードでも、コンテキストメニューキーで開ける）
- 4: 名前は全員の画面に出るので、送ってくるブラウザを信じず、サーバーで整える。参加者の名前と同じ考え方・同じ処理にすれば、検証の抜けが起きにくい。ほかのタブの名前や「ターミナル N」をまねると、別のタブに入力させるような偽装ができるので、番号を添えて見分けられるようにする

## 影響・今後の課題

- タブを閉じると、そのタブに付けた名前も消える
- 同時に名前を付けたときは、サーバーに後から届いたものが勝つ

## 含めないもの

- 名前をコマンドから付けること（OSC などで）
- 名前の色やアイコン
