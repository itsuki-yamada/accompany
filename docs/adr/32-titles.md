# ターミナルのタイトルを titles イベントで配り、サーバーで整えてから出す

- 日付: 2026-10-15
- ストーリー: #32

## 背景

コマンドが OSC 0 / OSC 2 で設定したタイトル（Claude Code の会話名、シェルの作業ディレクトリなど）を、ペインのバーに出す。タイトルは参加者全員で共有し、途中から参加した人にも今のタイトルを出す。次の 3 点を決める必要があった。

- `/ws/workspace` でタイトルをどう配るか（#21 で配置は `{ type: "tabs" }` になった）
- タブの名前をターミナルのタイトルにするか
- タイトルの中の制御文字や、極端に長い文字列をどう扱うか

タイトルを受け取るのは、各ターミナルのサーバー側の画面（`@xterm/headless`）の `onTitleChange` にする。PTY の出力はすでにこの画面に流しているので、OSC の解釈を自前で書かずに済み、出力が途中で切れて届いても正しく読める。

## 検討した選択肢

### 配り方

1. `tabs` イベントの各ターミナルの節（`{ type: "terminal", id }`）に `title` を足す
2. `{ type: "titles", titles: { [ターミナルの ID]: タイトル } }` という別のイベントを足し、参加したときと、どれかのタイトルが変わったときに配る
3. ターミナルごとの WebSocket（`/ws/terminals/:id`）で、そのターミナルのタイトルを送る

### タブの名前

1. タブの名前は「タブ N」のままにする
2. タブの名前を、そのタブの（最初の、またはフォーカスされた）ターミナルのタイトルにする

### 制御文字と長さ

1. 何もしない（ブラウザでは `textContent` で出すので HTML として解釈されることはない）
2. サーバーで、制御文字を取り除き、長さに上限を設ける

## 決定

- 配り方: 選択肢 2。`WorkspaceEvent` に `{ type: "titles"; titles: Record<string, string> }` を足す。空のタイトルは含めない。同じタイトルが続けて設定されたときは配らない
- タブの名前: 選択肢 1。「タブ N」のまま
- 制御文字と長さ: 選択肢 2。`TerminalSession` の `sanitizeTitle` で次のように整える
  - Unicode の制御文字（`\p{Cc}`。C0・C1・DEL）を取り除く
  - 双方向テキストの制御文字（U+061C、U+200E、U+200F、U+202A〜U+202E、U+2066〜U+2069）を取り除く
  - 改行にあたる文字（U+2028、U+2029、U+0085）は空白にする
  - 256 文字（コードポイント）を超えるものは 255 文字に切り詰め、末尾に `…` を付ける
- ブラウザでは、バーの「ターミナル N」の右にタイトルを出し、収まらない分は CSS（`text-overflow: ellipsis`）で省略する。全文は `title` 属性（ツールチップ）で出す

## 理由

- 配り方: シェルのプロンプトや Claude Code の状態表示で、タイトルは頻繁に変わる。`tabs` イベントに含めると、タイトルが変わるたびにブラウザが配置を組み直す（境界のドラッグ中は待つ、などの扱いも絡む）。フォーカス表示（`presence`）と同じく、配置とは別のイベントにする方が影響が小さい。ターミナルごとの WebSocket は表示中のタブのターミナルにしかつながないため、将来タブにタイトルを出すときに困る。`titles` には全タブのターミナルのタイトルが入る
- タブの名前: どのターミナルのタイトルを使うか（最初のもの、フォーカスされたもの）を決める必要があり、参加者ごとにフォーカスが違うため「全員で同じ画面」と両立させる規則が要る。このストーリーの完了条件（バーで見られる）には不要なので、シンプルな方を選んだ
- 制御文字: C0・C1 の制御文字は、サーバー側の画面が OSC を読む段階で取り除かれる（試したところ、C0 は無視され、C1 は OSC を打ち切った）。ただしこれは xterm.js の実装に頼ることになるので、念のためサーバーでも取り除く。双方向テキストの制御文字は OSC をそのまま通り、`abc` + U+202E + `def` のようなタイトルで表示を偽装できるため取り除く。改行にあたる文字はバーを 1 行に保つため空白にする。絵文字の結合に使う ZWJ（U+200D）などは残す
- 長さ: xterm.js は OSC を 10MB まで受け付けるため、上限がないと大きな文字列を参加者全員に配ることになる。256 文字あればバーとツールチップには十分。切り詰めたことがわかるよう `…` を付ける

## 影響・今後の課題

- `/ws/workspace` を受けるコードは、`titles` イベントを無視しても問題ない（同時に進んでいる #27・#28・#29・#33 で既存の分岐に影響はない）
- `TerminalSession` のコンストラクタに 3 つ目の引数（タイトルが変わったときに呼ぶ関数）を足した。`TerminalSession.title` で今のタイトルを読める
- 1 回の出力の中で何度もタイトルが変わったときは、`queueMicrotask` でまとめて 1 回だけ配る。出力をまたいで頻繁に変わるコマンドでは、そのたびに全員へ配る。問題になれば間引く
- OSC を出さないコマンド（実行中のプロセス名）を PTY から調べて出すこと、タブにタイトルを出すこと、ブラウザのタブ（`document.title`）に出すことは扱わない
