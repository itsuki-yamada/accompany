# ターミナルにドロップしたファイルの受け取り方

- 日付: 2026-10-14
- ストーリー: #29

## 背景

ブラウザのターミナルに画像やファイルをドロップして、そのパスをエージェント（Claude Code など）に渡したい。ブラウザからはドロップしたファイルのローカルのパスを取れず、またコマンドはサーバー上で動いているので、ファイルをサーバーにアップロードし、サーバー上のパスを貼り付ける必要がある。

アップロードはサーバーのファイルシステムに書き込む新しい経路になるので、次を決める必要がある。

- 経路の守り
- ファイルの大きさの上限
- ファイル名の扱い（パスの区切りや危険な文字）
- 保存先
- 後片付け
- 貼り付け方（クォート、Enter、複数ファイル）

## 検討した選択肢

### 経路

- A. ターミナルの WebSocket で、ファイルの中身を送る
- B. HTTP の `POST /api/uploads`（multipart/form-data）で送り、保存先のパスを JSON で返す。貼り付けはブラウザが行う

### 保存先

- A. コマンドの作業ディレクトリ（プロジェクト）の中
- B. OS の一時ディレクトリの中に、Accompany ごとのディレクトリを作る

### ファイル名

- A. サーバーが付けた名前（連番や UUID）にする
- B. 元のファイル名を、危険な部分を取り除いて使う

### 後片付け

- A. 残す
- B. Accompany を止めたら消す

## 決定

- **経路**: B。`POST /api/uploads` に、WebSocket と同じ守り（loopback の Host と、Host と同じ Origin からだけ受け付ける。それ以外は 403）を付ける
- **大きさの上限**: 1 回のアップロード（ドロップ）で 100 MB。超えたら 413 を返す
- **保存先**: B。起動時に `<OS の一時ディレクトリ>/accompany-XXXXXX/`（`mkdtemp`）を作り、ドロップ 1 回ごとに連番のディレクトリ（`1/`、`2/`…）を作って、その中に保存する
  - 共有の一時ディレクトリの下なので、既にあるものやシンボリックリンクをたどらない。連番のディレクトリは `mkdir`（recursive なし、0700）で作り、ファイルは排他作成（`wx`、0600）で書く。既にあればエラーにする
  - 保存先が消えていたら（または、シンボリックリンクになっている・持ち主が自分でない・ほかのユーザーが書き込めるなど、自分の作った 0700 のディレクトリでなくなっていたら）、同じパスを作り直さず、`mkdtemp` で新しい保存先を作り、それ以降はそちらを使う
- **ファイル名**: B。元のファイル名から次のように作る
  - パスの区切り（`/` と `\`）より前を捨て、最後の部分だけを使う（`../../x.txt` は `x.txt`）
  - 制御文字を取り除く
  - 先頭の `.`、`-`、空白を取り除く（`..`、隠しファイル、コマンドのオプションに見えるのを防ぐ）
  - 長すぎる名前は、拡張子が残るよう末尾の 60 文字にする（多くのファイルシステムの上限 255 バイトに収める）
  - 何も残らなければ `file` にする。同じドロップの中で名前がぶつかったら `2-`、`3-` を前に付ける
- **後片付け**: B。Accompany を止めたとき（SIGINT・SIGTERM・SIGHUP）に、保存先のディレクトリごと消す
- **貼り付け方**: ブラウザが、返ってきたパスをそのターミナルに xterm.js の `paste` で貼り付ける。Enter は送らない
  - 英数字と `_-.,/+@%:=` だけのパスはそのまま、それ以外の文字（空白など）を含むパスはシングルクォートで囲む
  - 複数のファイルは空白区切りで並べ、末尾に空白を 1 つ付ける（続けて指示を書けるように）

## 理由

- **経路**: ターミナルの WebSocket は端末の入出力のためのもので、バイナリは出力に使っている。HTTP の multipart にすると、ブラウザの `FormData` と Hono の仕組みをそのまま使え、実装が小さい。貼り付けをブラウザの `paste` で行うと、普段のペーストと同じく bracketed paste に対応した形でエージェントに届く
- **守り**: アップロードされたファイルのパスはターミナルに貼り付けられ、エージェントが読むので、別サイトのページや DNS rebinding から書き込まれないようにする。WebSocket と同じミドルウェアを使い、守りの基準をそろえる。ブラウザは同じオリジンでも POST には Origin を付けるので、Accompany の画面からは通る
- **大きさ**: スクリーンショットや小さなファイルを渡すのが目的なので、数 MB で足りる。動画などを渡すことも考えて余裕を持たせつつ、Bun の既定の上限（128 MB）より小さい 100 MB にした
- **保存先**: プロジェクトの中に置くと、git の差分に出たり、コミットされたりする。一時ディレクトリなら作業の邪魔をせず、エージェントからは絶対パスで読める。ドロップごとにディレクトリを分けると、元の名前のまま上書きせずに保存でき、ファイル名を見てエージェントや人が中身を推測しやすい
- **ファイル名**: 元の名前（例: `スクリーンショット 2026-10-14.png`）が残ると、エージェントにも人にも何のファイルかわかる。一方、名前は送り手が自由に決められるので、保存先の外を指す部分やオプションに見える部分は取り除く
- **後片付け**: ドロップしたファイルは、そのセッションでエージェントに渡すためのもので、Accompany を止めたあとは要らない。残すと一時ディレクトリにたまり続ける

## 影響・今後の課題

- Accompany が `SIGKILL` などで強制終了したときは消せない。OS の一時ディレクトリの掃除に任せる
- 起動したまま OS が一時ディレクトリを掃除して保存先が消えても、新しい保存先を作るので、そのまま保存できる。消えた保存先の名前は貼り付けたパスから知られているので、同じパスを作り直すと、ほかのユーザーが先にそのパスにシンボリックリンクを置き、アップロードを別の場所に書き込ませることができてしまう。そのため `mkdtemp` で推測できない名前の保存先を作り直す
- 保存先を確かめてから連番のディレクトリを作るまでの、ごく短い間に保存先が消されて置き換えられる競合は防げない（`openat` のようにディレクトリを開いたまま扱う API が Bun / Node にないため）。ファイル自体は排他作成で書くので、既にあるファイルやリンクを上書きすることはない
- ターミナルの外（分割の境目など）にドロップしたファイルは受け取らない。ブラウザがファイルを開いて画面から離れないよう、ページ全体でドロップの既定の動作を取り消す
- 起動中はドロップしたファイルが増え続ける。長時間使うときに問題になれば、古いものを消す仕組みを考える
- 大きさの上限を超えたときや、アップロードに失敗したときは、ターミナルの上に「アップロードできませんでした」と少しの間だけ出す。上限の値は画面に出していない
- 外部に公開する（認証 #7 など）ときは、誰がアップロードできるかを改めて考える
- クリップボードの画像の貼り付け（Ctrl+V）は、このストーリーでは扱わない。同じ `POST /api/uploads` を使って実装できる
