# ターミナルのリンクのクリックは、ブラウザだけで開く

- 日付: 2026-10-17
- ストーリー: #59

## 背景

Claude Code の出力の URL をクリックすると、同じページが 2 つ開いた。調べると次のことが分かった。

- Claude Code（全画面の表示）はマウスの報告モード（`?1000h` / `?1006h`）を有効にし、クリックを受け取ると、その位置のハイパーリンク（OSC 8）を自分でも開く（Accompany を動かしているマシンで `open` する）
- xterm.js は、マウスの報告モードが有効でも、リンクをクリックすると開く。同時に、そのクリックをアプリにも報告する
- そのため、ブラウザ（xterm.js）と Claude Code の両方で開く

当初の見当だった「OSC 8 のリンクと `WebLinksAddon` のリンクが重なって両方開く」は起きていなかった（xterm.js は 1 回のクリックで 1 つのリンクしか開かない）。ただし OSC 8 のリンクは xterm.js 標準の処理で確認ダイアログ（`confirm`）を出しており、ただの文字列の URL と動きが違った。

## 検討した選択肢

1. リンクの上での押下はアプリに報告せず、ブラウザだけで開く
2. マウスの報告モードが有効な間は、ブラウザではリンクを開かず、アプリに任せる
3. 何もしない（Claude Code 側の設定で、リンクを開く動きを止めてもらう）

OSC 8 のリンクの開き方については、次を検討した。

- a. xterm.js 標準のまま（確認ダイアログを出す）
- b. `linkHandler` で、ただの文字列の URL（`WebLinksAddon`）と同じく、確認なしで opener を切った新しいタブで開く

## 決定

1 と b を採る。

- `Terminal` の `linkHandler` と `WebLinksAddon` に同じ開き方（opener を切った新しいタブ）を渡す
- どちらのリンクも、マウスが上にあるかを hover / leave で覚えておく。アプリがマウスの報告モードを有効にしていて、リンクの上で押したときは、押下をアプリに報告しない（xterm の画面の要素で `stopPropagation` し、アプリへの報告を受け取る外側の要素に届かないようにする）
- リンクのないところのクリック、マウスの報告モードが無効なときの動き（選択など）は変えない

## 理由

- 2 だと、アプリが開くのは Accompany を動かしているマシンなので、別のマシンから参加している人のブラウザでは開かない。リンクを解釈しないアプリでは、どこでも開かなくなる。1 なら、クリックした参加者のブラウザで必ず 1 つ開く
- 3 は利用者に設定を求めることになり、Claude Code 以外の同じ動きのアプリにも効かない
- b は、OSC 8 とただの URL で動きが揃い、Claude Code のように URL を OSC 8 で出すアプリでも、毎回確認を挟まずに開ける。開く先は http / https に限る（xterm.js の既定のまま）

## 影響・今後の課題

- アプリはリンクの上のクリックを受け取らなくなる。リンクの上のクリックで、リンクを開く以外のことをするアプリでは、その動きが使えない。困る例が出たら、修飾キーを押しているときはアプリに渡すなどを検討する
- OSC 8 のリンクは、表示の文字と行き先の URL が違うことがある。確認ダイアログをやめたので、行き先はブラウザで開いたタブで確かめることになる。必要になったら、ホバーで行き先を見せることを検討する
- xterm の内部の要素（`.xterm-screen`）とイベントの順番に頼っている。xterm.js を上げるときは E2E（`e2e/tests/links.spec.ts`）で確かめる
