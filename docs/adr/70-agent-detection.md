# エージェントが前面で動いているターミナルだけで、エージェントの状態を判定する

- 日付: 2026-10-18
- ストーリー: #70

## 背景

[ADR 28](28-agent-status.md) では、エージェントの状態（作業中・入力待ち）を PTY の入出力の続き方だけで判定していた。そのターミナルでエージェントが動いているかどうかは見ていないので、次のことが起きていた。

- シェルで `watch` やビルドなど、出力の続くふつうのコマンドを動かしても「作業中」「入力待ち」になり、作業が終わったという通知も出る
- シェルから `claude` を起動すると、Enter のあとの起動の描画（約 1.5 秒）を「入力のあとの出力」と数え、何もしていないのに作業中 → 入力待ちになって通知が出る（実物の Claude Code v2.1.302 で再現した。起動時のコマンドとして直接動かしたときは、入力がないので起きない）
- 「入力待ち」は、ほかの参加者の入力を待っているようにも読める

[herdr](https://herdr.dev/docs/concepts/) は、ターミナルの前面で動いているプロセスからエージェントを見分け、エージェントが動いているところだけに状態を出している。

## 検討した選択肢

### エージェントの見分け方

1. **PTY の前面のプロセスグループを調べる**: 端末の前面のプロセスグループ（`tcgetpgrp`）に属するプロセスの名前を見る
2. **起動したプロセスの子孫を調べる**: シェルの子・孫をたどり、エージェントの名前のものがあるかを見る
3. **画面の内容やタイトル（OSC 0/2）から見分ける**: エージェントごとの画面の特徴やタイトルを見る

### 前面のプロセスグループの取り方

- a. PTY のマスター側の fd に `tcgetpgrp` を呼ぶ: Bun の `Bun.spawn` の `terminal` は fd を公開していない（`write`・`resize`・`setRawMode`・`close` などだけ）。FFI で呼ぶと、Bun の内部に依存する
- b. `ps` の `tpgid`（制御端末の前面のプロセスグループ）を見る: macOS と Linux（procps）の両方で使える

### 調べる頻度

- 一定間隔で調べ続ける
- 出力のたびに調べる
- 入出力があってから間を置いて調べる

## 決定

- 選択肢 1 を、b の方法で行う。起動したプロセスの制御端末（`ps -o tty= -p <pid>`、最初に 1 回だけ調べて覚える）にいるプロセスを `ps -ww -o pgid=,tpgid=,args= -t <tty>` で 1 回で取り（`-ww` は、Linux の procps が端末の幅で引数を切り詰めないように）、プロセスグループが `tpgid` と同じもの（前面のもの）の引数を見る
- 前面のプロセスの引数の 1 語目の名前（パスの最後）が、エージェントとみなす名前なら、エージェントが動いているとみなす。1 語目が `node`・`nodejs`・`bun`・`deno`・`python*` のときは、オプションでない次の語（スクリプトのパス）の名前を見る。名前の `.js`・`.mjs`・`.cjs`・`.ts`・`.py` は除く
- エージェントとみなす名前は固定にする: `claude`、`codex`、`gemini`、`opencode`、`aider`、`cursor-agent`、`copilot`、`qwen`、`amp`
- 調べるのは、入力か出力があってから 0.5 秒たったとき。調べる予定があるうちや、調べている間は重ねない。調べている最中に入出力があったら、調べ終えてから改めて予定を作る（最中に前面が替わり、それが最後の入出力だと、古い結果が残ってしまうため）。入出力のないターミナルは調べない
- `ps` が 2 秒で終わらなければ止めて、そのときは調べられなかったもの（前の結果のまま）とする
- エージェントが前面になった時点（前面のプロセスグループが別のエージェントに替わったときも）で、ADR 28 の判定をそれまでの入出力を忘れてやり直し、「指示待ち」から始める。エージェントが前面にいない間の判定の変化は配らない
- 配る `status` イベント（`statuses`）には、エージェントが前面で動いているターミナルだけを含める。含まれないターミナルでは状態を出さない
- 状態の表記は「作業中」と「指示待ち」にする。通知の題も「ターミナル N: 指示待ち」にする
- エージェントが動いているターミナルは、バーの背景と下の線を、参加者に割り当てない色（`#64ffda`）にして目立たせる。フォーカスの枠（ペインの外枠を参加者の色にする）は今までどおりで、両方を同時に出せる

## 理由

- **前面のプロセスグループにする理由**: シェルのジョブ制御は、いま端末を使っているジョブを前面のプロセスグループにする。前面を見れば「いまそのターミナルで動いているもの」が分かり、裏で動かしているもの（`&` で動かしたもの）やシェル自身は除ける。子孫をたどる方法（選択肢 2）は、裏のジョブやエージェントが起動した子プロセス（エージェントの中のシェルなど）まで拾うので、前面かどうかの判断が別に要る。画面やタイトル（選択肢 3）は、エージェントの版で変わりやすい
- **`ps` にする理由**: Bun の PTY から fd を取れないので、`tcgetpgrp` を直接呼べない。`ps` は macOS と Linux のどちらにもあり、`-t` と `tpgid` はどちらでも同じように使える。`-t` で端末のプロセスだけを取るので、1 回 5 ミリ秒ほどで済む（全プロセスを取る `-A` は 20〜50 ミリ秒）
- **引数（args）を見る理由**: コマンド名（`comm`）ではエージェントを見分けられないことがある。Claude Code のネイティブ版は実行ファイルが `~/.local/share/claude/versions/2.1.302` なので、`comm` は版の番号になる。npm で入れた Node 製の CLI（Gemini CLI など）は `node /usr/local/bin/gemini` として動くので、`comm` は `node` になる。引数の 1 語目はシェルが打たれたとおりの名前（`claude`）を渡すので、こちらで見分けられる
- **名前を固定にする理由**: まずは主なエージェントで足りる。設定で増やせるようにすると、設定の置き場所と画面が要る。足りない名前があれば一覧に足す
- **間を置いて調べる理由**: 出力のたびに `ps` を起動すると、出力の多いコマンドでプロセスの起動が続く。エージェントの起動・終了はシェルへの入力（Enter）か、シェルのプロンプトの出力を伴うので、入出力のあとに調べれば気づける。0.5 秒の遅れは、状態の表示には十分短い
- **前面になったときに判定をやり直す理由**: シェルから起動すると、起動のための Enter のあとに起動の描画が続くので、ADR 28 の規則のままでは作業と数えてしまう。前面になった時点で入力の時刻を忘れれば、そのあとの起動の描画は「入力のあとの出力」にならない。エージェントを見分けるのが起動の描画の途中でも、終わったあとでも、同じ結果になる
- **`status` イベントからエージェントでないものを除く理由**: 状態を出すかどうかを、受け取る側が別の値（`"none"` など）で分けなくて済む。含まれないものを「エージェントが動いていない」と読めばよい
- **「指示待ち」にする理由**: 「入力待ち」は、ほかの参加者の入力を待っているようにも読める。エージェントが参加者からの次の指示（プロンプトや承認）を待っていることを、そのまま書く
- **目立たせ方**: 参加者のフォーカスは外枠を参加者の色にしているので、同じ外枠を使うと区別がつかない。バーの背景と下の線を、参加者の色（青・橙・緑・桃・紫・黄）と重ならない色にすれば、フォーカスの枠と同時に出しても区別できる

## ADR 28 との関係

- ADR 28 の判定の規則（入力のあとに出始めた出力を数える、1 秒続いたら作業中、2 秒途切れたら止まった、エコーや自動の応答を数えない）と通知の条件はそのまま使う。この ADR は、その判定を「エージェントが前面で動いている間だけ」に絞り、始める時点を「エージェントが前面になったとき」にする
- ADR 28 の「影響・今後の課題」で許容していた、ふつうのコマンド（ビルドのログなど）でも作業中になって通知が来ることは、やめる。ふつうのコマンドの終わりを知らせる機能が欲しくなったら、別のストーリーで扱う
- 表記の「入力待ち」は「指示待ち」に変える

## 影響・今後の課題

- `status` イベントの形が変わる: これまではすべてのターミナルを含み、値は `"working"` か `"idle"` だった。これからは、エージェントが前面で動いているターミナルだけを含む（値は同じ）。この値を使う機能（サイドメニューなど）は、含まれないターミナルを「エージェントが動いていない」と扱う
- シェルから `claude "…"` のようにプロンプトを付けて起動し、すぐに作業を始めた場合は、そのあと参加者が入力するまで作業中にならない（起動の描画と見分けられないため）。終わったときの通知も出ない
- `npx`、`bunx` や、独自のラッパースクリプトから起動すると、前面のプロセスの名前がエージェントの名前にならず、見分けられないことがある（`npx` の子として動くエージェントのプロセスが前面のグループにいれば見分けられる）
- 前面のプロセスグループが変わらないまま中身が替わった場合（シェルを経ずにエージェントが別のエージェントを起動するなど）は、エージェントが続いているとみなす
- `ps` のない環境（BusyBox の一部など）では、エージェントを見分けられず、状態を出さない
- 名前だけで見分けるので、`node`・`bun`・`python` で動かすふつうのスクリプトでも、名前が `claude` などならエージェントとみなす。`amp` のような短い名前は、エージェントでない同じ名前のコマンドとぶつかることがある
- 作業中にエージェントが終わった（前面がシェルに戻った）ときは、状態を消すだけで、作業が終わったという通知は出さない
- エージェントとみなす名前を利用者が増やす設定は、要望があれば足す
