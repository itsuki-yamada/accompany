# 作業が終わってまだ誰も見ていないエージェントを「未確認」と出し、誰か 1 人が見たら全員から消す

- 日付: 2026-10-20
- ストーリー: #74

## 背景

エージェントの状態は「作業中」と「指示待ち」の 2 つだけで（[ADR 28](28-agent-status.md)、[ADR 70](70-agent-detection.md)）、作業が終わったばかりで結果をまだ見ていないものと、見終わってずっと指示待ちのものの区別がつかない。サイドメニュー（[ADR 72](72-sidebar.md)）でも、どの Workspace に見るべき結果があるかが分からない。

[herdr](https://herdr.dev/docs/concepts/) には done（作業が終わり、まだ見ていない）の状態があり、そのペインを見ると idle に戻る。

## 検討した選択肢

### 「見た」を誰の単位で持つか

1. **参加者ごと**: 各参加者のブラウザが、自分が見たかを持つ。ほかの参加者が見ても、自分の画面では未確認のまま
2. **全員で 1 つ（サーバーで持つ）**: 誰か 1 人が見たら、全員の表示から未確認を消す

### 「見ている」をどこで決めるか

- a. 各ブラウザが条件を判断し、見たら「見た」とサーバーに送る
- b. 各ブラウザはページが見えているか（`document.hidden`）だけをサーバーに送り、サーバーが表示中の Workspace とフォーカス先と合わせて判断する

### 表記

- 「完了」: エージェントそのものが終わった（プロセスが終わった）とも読める
- 「終わった（未確認）」: 意味ははっきりするが、件数の印（「終わった（未確認） 1」）がサイドメニューの幅に収まりにくい
- 「未確認」: 短い。ストーリーの言い方（「未確認」が消えて通常の入力待ちになる）とも同じ

## 決定

- **2（全員で 1 つ）を、b の方法で行う**。ターミナルごとに「作業が終わってまだ誰も見ていない」をサーバーが持つ（`TerminalSession` の `unseen`）。配る `status` イベントの値に `"done"` を足し、作業中から指示待ちに変わって未確認のものを `"done"` にする
- **見ている** = 表示中の Workspace にあり、その参加者がそのターミナルにフォーカスしていて（最後にフォーカスしたターミナル）、ページが見えている。条件は通知を出さない条件（ADR 28）と同じ
- 各ブラウザは、接続したときとページの見え方が変わったときに `{ type: "visibility", visible }` を送る。サーバーは、届くまではページが見えていないとみなす
- サーバーは次のときに、見ている参加者がいるターミナルの未確認を消し、変わったら全員に配る: 作業が終わったとき（見ている人がいれば、未確認にしないで指示待ちとして配る）、フォーカスが移ったとき、ページの見え方が変わったとき、表示中の Workspace や配置が変わったとき
- 未確認のまま次の作業を始めたら作業中になり、未確認は消える。エージェントが前面でなくなった・別のエージェントに替わったときも消える
- 表記は「未確認」。ツールチップに「作業が終わったが、まだ誰も見ていない」と出す。色と形は、指示待ち（`#64ffda` の枠）と同じエージェントの色で塗りつぶし、文字を太字にする（作業中は黄 `#ffd54f` の枠）。ターミナルのバー、サイドメニューのセッションの一覧、Workspace とセッションの件数（「作業中」「未確認」「指示待ち」の順）に同じ表記と色で出す。件数が 3 つに増えるので、セッションの見出しの全体の件数も、Workspace の印と同じく 0 件の状態は出さない（ADR 72 では見出しだけ 0 件も出していた）
- 未確認は保存しない。再起動するとエージェントは起動し直しになり、状態も指示待ちから始まるため
- 通知は、作業中から指示待ちか未確認に変わったときに、これまでの条件で出す。題は「ターミナル N: 指示待ち」のまま

## 理由

- **全員で 1 つにする理由**: ペアプロでは全員が同じ画面を見て、同じ結果を確かめる。誰かが見て判断したものが、ほかの人の画面で未確認のまま残ると、もう見たものを探しに行くことになる。表示中の Workspace も全員で共有している（[ADR 21](21-tabs.md)）ので、見たかどうかも全員で揃えるのが自然。参加者ごとにすると、途中から参加した人にとってはすべてが未確認になるか、何を見たかをサーバーに参加者ごとに持つ必要がある
- **サーバーで判断する理由（b）**: 作業が終わった時点で見ている人がいれば、未確認を経ずに指示待ちとして配れる。ブラウザが「見た」と送る方法（a）だと、一度全員に未確認が配られてから消えるので、見ていた人の画面でも未確認が一瞬出る。表示中の Workspace とフォーカス先はもうサーバーにあり、足すのは参加者ごとのページの見え方（真偽値 1 つ）だけで済む
- **「未確認」にする理由**: 状態の印として、作業中・指示待ちと並べて短く読める。「完了」は、エージェントが終わった（もう動いていない）と読み違えやすい。意味はツールチップで補う
- **色**: 未確認は指示待ちの一種なので、同じエージェントの色にして、塗りつぶしと太字で目立たせる。別の色で塗りつぶす案（青 `#82b1ff`）も試したが、バーとセッションの一覧では、参加者の名前の印（参加者の色で塗りつぶす。青 `#4fc3f7` など）と並び、見分けにくかった。エージェントの色は参加者に割り当てない（ADR 70）ので混ざらない
- **保存しない理由**: 再起動すると、戻したターミナルではシェル（起動時のコマンド）を新しく起動するので、前のエージェントの作業の結果は画面のスクロールバックにしか残らない。サーバーに保存するものを増やさない

## 影響・今後の課題

- `status` イベントの値に `"done"` が増える。値を使う機能（ターミナルのバー、サイドメニュー、通知）は、`"done"` を指示待ちの一種として扱う
- 誰かがページを開いたまま、別のターミナルに目を向けずにフォーカスだけが残っていても「見た」とみなす。フォーカスの先と目線は一致しないことがあるが、通知を出さない条件と揃えた
- ページが見えていても、ブラウザのウィンドウが背面にあるとき（`document.hasFocus()` が偽）は「見た」とみなす。通知の条件（ADR 28）と同じ
- 参加者ごとに「見た」を分けたくなったら（たとえば、参加者ごとに別の Workspace を表示できるようにしたとき）、見直す
- 「承認待ち（herdr の blocked）」の区別は入れていない
- ADR 72 の「区別できるようになったら、セッションの一覧を表示中の Workspace だけに絞ることも検討する」は、この ADR では行わない。未確認が増えても全件の一覧から 1 回で移れるため
