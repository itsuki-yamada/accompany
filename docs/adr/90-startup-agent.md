# 起動時のコマンドとして動かしたエージェントは、見分けたときにそれまでの入出力を忘れない

- 日付: 2026-10-23
- ストーリー: #90

## 背景

[ADR 70](70-agent-detection.md) では、入出力があってから 0.5 秒たったときに前面のプロセスを調べ、エージェントが前面になった時点で ADR 28 の判定をやり直す（`ActivityMonitor.reset()` でそれまでの入出力を忘れる）。シェルから `claude` を起動したときの、起動の Enter とそのあとの起動の描画を作業と数えないためである。

起動時のコマンドとして直接動かしたエージェント（`accompany -- claude`）では、エージェントだと見分ける前に参加者が最初の指示を出すことがある（起動の描画のあと 0.5 秒と `ps` の時間が過ぎる前に打った、`ps` が遅かった、など）。その場合、最初の指示の入出力のあとに初めてエージェントだと見分け、`reset()` でその指示の入力も忘れるので、最初の作業で「作業中」にならず、終わっても通知が出なかった。

## 検討した選択肢

1. **起動した時点で調べる**: コマンドを起動した直後（最初の出力より前）にも前面のプロセスを調べる
2. **起動時のコマンド自身のプロセスグループなら忘れない**: 前面になったエージェントのプロセスグループが、起動時のコマンドのもの（番号が起動したプロセスの pid と同じ）なら、`reset()` しない
3. **直前の入力が指示なら忘れない**: `reset()` のときに、直前の入力が参加者の指示だったかを見て、指示なら残す

## 決定

選択肢 2 にする。エージェントが前面になった（別のエージェントに替わった）とき、そのプロセスグループの番号が起動時のコマンドの pid と同じなら、判定をやり直さず、それまでの入出力（と未確認）をそのまま使う。状態を配るのは今までどおり（前面になった時点で配る）。それ以外のプロセスグループ（シェルから起動したもの）は、今までどおり `reset()` する。

## 理由

- **`reset()` が要るのは、シェルへの Enter で起動したときだけ**: 忘れたいのは「起動のための Enter」と、そのあとの起動の描画である。起動時のコマンドは Accompany が直接起動するので、そのような Enter がない。起動の描画は、入力のあとに出始めた出力ではないので、`reset()` しなくても ADR 28 の規則で数えない
- **起動時のコマンドを見分けられる**: Bun は PTY 付きで起動したプロセスを新しいセッションのリーダーにするので、そのプロセスグループの番号は pid と同じになる。シェルのジョブ制御は、シェルから起動したジョブを別のプロセスグループにするので、シェルから起動したエージェントとは区別できる
- **選択肢 1 では足りない**: 起動の直後に調べても、`ps` が終わる前（ふつうは数ミリ秒、遅い環境では 1 秒を超える）に打った指示は同じように忘れる。起動の直後には、まだラッパーがエージェントを起動していないこともある。見分ける時刻に頼らない選択肢 2 なら、いつ見分けても同じ結果になる
- **選択肢 3 は、シェルから起動したときと区別できない**: シェルで `claude` と打った Enter も参加者の入力で、指示と見分けられない。残すと、シェルから起動したときの起動の描画を作業と数えてしまう（[ADR 70](70-agent-detection.md)、#90 の完了条件 2）

## ADR 70 との関係

- ADR 70 の「エージェントが前面になった時点で、ADR 28 の判定をそれまでの入出力を忘れてやり直す」を、シェルなどから起動した（起動時のコマンドとは別のプロセスグループの）エージェントに限る。見分け方、調べる時刻、状態を配る範囲は変えない
- 起動時のコマンドのエージェントでも、見分けるまでは状態を配らないのは同じ。見分けた時点で、それまでの判定（作業中か、終わって未確認か）を配る

## 影響・今後の課題

- 起動時のコマンドのエージェントを見分ける前に作業が終わった場合は、見分けた時点で「未確認」（誰かが見ていれば「指示待ち」）を配るが、作業が終わったという通知は出ない（通知は作業中から指示待ちへの変化で出すため）。作業が見分けるまでの時間（0.5 秒と `ps` の時間）より長ければ、通知も出る
- 起動時のコマンドが `sh -c 'claude'` のような対話でないシェルで、ジョブ制御をしないものなら、エージェントは起動時のコマンドと同じプロセスグループで動くので、同じく忘れない。そのシェルへの Enter はないので、これでよい
- ADR 70 の、シェルから `claude "…"` のようにプロンプトを付けて起動したときに最初の作業を数えない件は、変わらない

## 含めないもの

- 起動した直後に前面のプロセスを調べること（選択肢 1）。状態を早く出すためのもので、今回の不具合には効かないので入れない
