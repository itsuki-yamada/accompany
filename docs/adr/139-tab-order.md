# タブの並び順を変える

- 日付: 2026-10-23
- ストーリー: #139

## 背景

#100（docs/adr/100-terminal-tabs.md）で、ターミナル 1 つが 1 つのタブになり、サイドメニューとツールバー（サイドメニューを隠している間）にタブが開いた順に並ぶようになった。使い道に合わせて（例: app、env、e2e の順）並び順を変えたい。

迷ったのは、次の点。

1. 並び順を全員で共有するか、参加者ごとにするか
2. マウス以外での並べ替えの操作
3. サーバーへの伝え方と検証

## 検討した選択肢

1. 共有するか
   - A. サーバーが持つタブの並び（`tabs`）そのものを変え、全員で共有する
   - B. 参加者ごとに並び順を持つ（サーバーの並びはそのままで、ブラウザが並べ替えて出す）
2. マウス以外の操作
   - A. ショートカット（⌘⇧ と何かのキー）を足す
   - B. タブにキー入力しているときの Alt（Option）+矢印と、タブの右クリックのメニュー（上へ・下へ移す、左へ・右へ移す）
3. 伝え方
   - A. 移すタブと、並べ替えたあとの位置（`{ type: "move-tab", tab, index }`）を送る
   - B. 並び全体を送る

## 決定

1 は A、2 は B、3 は A を採る。

- 並び順はサーバーが持つタブの並びで、全員で共有する。変えると全員に `tabs` を配り直し、保存する（session-store の version 2 の `tabs` がそのまま並びなので、形式は変えない）。再起動すると保存した並びで戻り、新しいタブはこれまでどおり最後に足す
- 参加者ごとの表示（選んでいるタブと分割）と、ペアプロモードの追従は変えない。並べ替えは表示を変える操作ではないので、ペアプロモードもやめない
- 次・前のタブ（⌘⇧. / ,）は、これまでどおりサーバーから届いた並びに従うので、新しい並びで移る
- ドラッグ: サイドメニューのタブの行と、ツールバーのタブの項目を、HTML のドラッグ・アンド・ドロップで動かす。ほかのタブの前半（サイドメニューは上半分、ツールバーは左半分）に重ねるとその前、後半に重ねるとその後ろへ移し、移す位置に線を出す。ドラッグしているタブは薄くする。ドラッグを受け付けるのは、そのページのタブだけ（ファイルやほかのページからのドラッグは、これまでどおりターミナルへのファイルのドロップとして扱う）。ドラッグしている間に届いた一覧は、組み直すとドラッグしている要素がなくなるので、手を離してから出す。手を離したときは、その一覧を出してから、その並びで移す位置を数える（ドラッグしている間にほかの参加者が並べ替えても、重ねたタブの前・後ろへ移る）
- キーボード: サイドメニューのタブにキー入力しているときは Alt（Option）+↑↓、ツールバーのタブでは Alt（Option）+←→ で、前・後ろへ移す。端ではそれ以上動かないが、キーの既定の動作は止める（Windows・Linux の Chrome では Alt+←→ が「戻る・進む」なので）。移したタブにキー入力の先が残るので、続けて押して何段も動かせる。ショートカットの一覧に、マウスの操作と同じく一覧にだけ出す行として載せる
- 右クリックのメニュー: タブを右クリック（またはコンテキストメニューキー）すると、サイドメニューでは「上へ移す」「下へ移す」、ツールバーでは「左へ移す」「右へ移す」を出す。端のタブでは、その向きの項目を選べなくする
- 続けて移したときに、前の並びから位置を数えないよう、ブラウザはサーバーから並びが届く前に手元の並びも変えておく。届いた並びで置き換わる
- サーバーは、`tab` が文字列、`index` が整数のものだけを受け付け、ないタブ、範囲外の位置（0 未満、タブの数以上）は無視する

## 理由

- 1: 並び順はタブの一覧の見た目で、「どのタブを見ているか」（参加者ごと）とは別のもの。同じ作業を一緒にしている人どうしで「上から 2 つ目」が同じタブを指すほうが話しやすい。サーバーがすでに並びを持っていて保存もしているので、変える場所が 1 つで済む。参加者ごとにすると、⌘⇧. / , の順や保存の扱い（参加者は開き直すと別人になる）を別に決める必要がある
- 2: ⌘⇧ の組み合わせは空きが少なく、Chrome がタブの移動に使う Ctrl+Shift+PageUp / PageDown はページに届かない。タブにキー入力しているときだけ効くキーなら、ターミナルのキー（シェルや TUI が使う Alt+矢印）を奪わない。Alt+矢印は、一覧の項目を動かすキーとして VS Code などでもなじみがある。右クリックのメニューは、キーを知らなくても見つけられる
- 3: 移すタブと位置だけなら、ほかの参加者が同時にタブを開いたり閉じたりしても、知らないタブを消したり戻したりしない。並び全体を送ると、受け取ったときに並びと食い違っていないかを確かめる必要がある

## 影響・今後の課題

- ほかの参加者が並べ替えると、自分の一覧の並びも変わる。ドラッグしている間は、手を離すまで変わらない
- 同時に並べ替えたときは、サーバーに後から届いたものが勝つ

## 含めないもの

- 参加者ごとの並び順
- 分割の中でのターミナルの位置の入れ替え（表示の並べ方は分割の操作で決める）
- タブの名前を変えること（#110）
