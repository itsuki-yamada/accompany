# ほかの参加者のフォロー

- 日付: 2026-10-18
- ストーリー: #69

## 背景

ペアプロで、ドライバーがいまどのターミナルを見ているかをナビゲーターが追いかけられるよう、Figma や Live Share のように、ほかの参加者をフォローして自分のフォーカスを追従させる。タブの切り替えと分割の配置はもともと全員で共有していて、参加者ごとのフォーカス先もサーバーが presence で全員に配っている。

迷ったのは、次の点。

1. フォローの状態をどこに持つか
2. フォローされている側に、誰にフォローされているかを見せるか
3. 「自分で操作したのでフォローをやめる」を、どう見分けるか
4. フォローを始める入り口と、フォロー中の見せ方

## 検討した選択肢

1. 状態の置き場所
   - A. 各参加者のブラウザだけに持つ。相手のフォーカス先は、いまの presence をそのまま使う
   - B. サーバーに「誰が誰をフォローしているか」を持ち、presence で配る
2. フォローされている側への表示
   - A. 出さない
   - B. 「参加者 2 がフォロー中」のように出す（1 の B が要る）
3. 自分の操作の見分け方
   - A. キー入力の先が変わったこと（xterm の入力欄の focus イベント）で見分け、フォローで移したときだけ印を付けて除く
   - B. 自分の操作そのもの（ターミナルのクリック・右クリック・バーのボタン、隣のターミナルへ移るショートカット、通知のクリック）でやめる
4. 入り口と見せ方
   - A. ターミナルのバーに出ている、ほかの参加者の名前をボタンにする。フォロー中はタブバーに「参加者 N をフォロー中」と「フォローをやめる」を出し、画面の縁を相手の色で囲む
   - B. 参加者の一覧を別に作り、そこから選ぶ

## 決定

1 は A、2 は A、3 は B、4 は A を採る。

- フォローは `public/index.ts` の変数（`following`）だけで持ち、サーバーには何も足さない
- 参加者のフォーカス先が届くたびと、配置を組み立てたときに、相手のフォーカス先のターミナルが表示中のタブにあり、自分のフォーカスがそのターミナルになければ、そこに移す（最後に移した先ではなく、実際のフォーカスで判断する）。移したことは、ふだんどおり focus としてサーバーに伝わるので、自分の名前も相手と同じターミナルに出る
- ただし、タブバーや設定・コマンドの管理の画面など、配置の外にフォーカスがあるときは持っていかない（入力の途中で奪わないため）
- フォーカスは、#68 の拡大と同じ移し方（拡大を決め直してから移す）で移す。自分の画面で拡大していて相手の移った先が隠れていても移れ、移った先が枠に収まらなければ、自分の画面でそのターミナルを拡大する。拡大の状態（どれを拡大しているか、拡大を外しているか）そのものは追従しない
- 相手のフォーカス先が表示中のタブにないとき（タブの切り替えと行き違ったときなど）は何もせず、配置が届いて組み立てたときに移す。フォローのためにタブは切り替えない
- 次のときにフォローをやめる: 相手と別のターミナルを自分で操作した（クリック、右クリック、バーの検索・コマンド・分割などのボタン。ほかの参加者の名前のボタンは除く）、隣のターミナルへ移るショートカットを押した、通知をクリックした、フォローをやめるボタンか相手の名前をもう一度押した、相手が抜けた（presence からいなくなった）
- 相手と同じターミナルをクリックしたり、そこに入力したりしても、フォローは続ける

## 理由

- 1・2: フォローは見る側の都合で、サーバーにも相手の画面にも影響しないのが自然。サーバーに状態を増やさずに済み、ストーリーの完了条件（フォローされている側の画面や操作は変わらない）とも合う。誰に見られているかは、いまでもバーの名前（相手のフォーカス先に、フォローしている人の名前も並ぶ）である程度分かる
- 3: focus イベントで見分ける方法は、フォロー以外の理由でもフォーカスが動く（配置を組み直したときに戻す、閉じたターミナルの隣に移す）うえ、ウィンドウが前面にないと Chrome は focus イベントを前面に戻るまで遅らせるので、フォローで移したものかの印と食い違いやすい。操作そのものでやめれば、フォローで移したフォーカスを誤って「自分の操作」とみなすことがない
- 4: 相手の名前は、相手がいまいるターミナルのバーに出ているので、「この人を追う」と押す場所として分かりやすい。別の一覧を作るより変更が小さい。縁の色は、Figma のフォロー中の表示にならった。縁は outline で中に重ねて描き、配置の大きさ（端末の大きさの計算）を変えない

## 影響・今後の課題

- フォローされている側は、誰にフォローされているかを知る専用の表示がない。必要になったら、presence に「フォロー中の相手」を足して出す（1・2 の B）
- どのターミナルにもフォーカスしていない参加者（開いた直後で、まだ presence にフォーカス先がない人）は、バーに名前が出ないのでフォローできない。開くと最初のターミナルにフォーカスするので、ふつうは起きない
- タブを Tab キーで移るなど、ここに挙げた以外の操作では、フォローをやめない
- 追従するのはフォーカス先（どのターミナルか）だけで、スクロール位置や選択範囲、#68 の拡大表示は追従しない
