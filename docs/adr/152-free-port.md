# ポートが使われていたら、空いているポートまで上げて起動する

- 日付: 2026-10-23
- ストーリー: #152（#147 から分けたもの）

## 背景

指定したポート（既定 3000）がほかのプロセスに使われていると、Accompany は Bun の `EADDRINUSE` の例外（スタックつき）で起動に失敗していた。開発用のサーバーなどが 3000 を使っていることは多い。持ち主のコメント（#147）で「port が被っているときは port 番号をインクリメントして空いている port で立つようにする」と決まった。

決める必要があったのは次のこと。

- `--port` を明示したときも上げるか
- 上げる回数の上限
- 既存の E2E「同じポートで Accompany が動いているときは、起動に失敗する」をどうするか

## 検討した選択肢

### `--port` を明示したとき

1. 既定のポートでも明示したポートでも、同じように上げる
2. 明示したときは上げずに失敗する（Vite の `--strictPort` のように、上げない指定を別に設ける案も含む）

### 上限

1. 空くまで（65535 まで）上げる
2. 決まった数（10 個）まで上げ、空かなければエラーにする

## 決定

- `--port` の有無によらず、指定したポートが使われていたら 1 つずつ上げて待ち受ける（選択肢 1）
- 上げるのは、指定したポートから 10 個（`<ポート>`〜`<ポート>+9`。65535 を超えない）まで。すべて使われていたら `Accompany: ポート 3000〜3009 はすべて使われています。--port で別のポートを指定してください` を標準エラーに出し、終了コード 1 で終わる（スタックは出さない）
- 上げたときは、`Accompany: ポート 3000 は使われているので、3001 で待ち受けます` を出してから、いつもの `Accompany: http://127.0.0.1:3001` を出す。前の行には URL を入れない（URL を探して使う人や道具が、最初の URL を実際のものとみなせるように）
- 上げるのは `EADDRINUSE` のときだけ。ほかの例外（権限がないなど）は、これまでどおりそのまま投げる
- 同じポートで二重に待ち受けない（`reusePort: false`）ことは変えない。既存の E2E は「同じポートで Accompany が動いているときは、次の空いているポートで起動し、そのポートを表示する」に変えた。2 つ目は次のポートで起動し、1 つ目は元のポートでそのまま使える、を確かめる
- 画面のファイルの用意（`compressedRoutes`）は、ポートを試す前に一度だけ行う
- すべて使われていて終わるときは、待ち受ける前に起動した最初のターミナルのコマンドを止め（`killAll`）、ドロップしたファイルの置き場を消してから終わる。待ち受けを Workspace より先にする案もあったが、`createApp` が Workspace を要るので、終わる経路で片づけるほうが変更が小さい
- `--port` の値は、ポートを試す前に `cli-args.ts` で確かめる。0〜65535 の整数（数字だけ）でなければ、`Accompany: --port は 0〜65535 の整数で指定してください: <値>` と使い方を標準エラーに出し、終了コード 1 で終わる。確かめないと、`--port abc` で「ポート NaN〜NaN はすべて使われています」、`--port 70000` で「ポート 70000〜65535 はすべて使われています」のように、誤ったエラーになる
- あわせて、#147 で英語のまま残っていた `parseArgs` の説明を日本語にそろえる。`--port --fresh`（値の要るオプションのあとに別のオプション）は `--port には値が要ります`、`--fresh=x`（値を取らないオプションに値）は `--fresh は値を取りません`
- `--help` の `--port` の説明に、使われていたら上げる（10 個まで）ことを足す

## 理由

- 持ち主の方針は「被っているときは上げる」で、明示したときを除くとは書かれていない。`--port 4000` を指定した人も、4000 が使われていれば起動できないより起動できるほうがよい。実際に待ち受けたポートは URL と前の行で分かる
- 明示したときに失敗させたい場面（Live Share で共有するポートを固定したいなど）でも、表示された URL のポートを共有すればよい。必要になったら、上げない指定を足す
- 上限なしに上げると、ほとんど使われている範囲を延々と試し、思いもよらないポートで起動しうる。10 個使われていれば、利用者が `--port` で選び直すほうが分かりやすい
- 1 つずつ試して待ち受ける（先に空いているか調べない）ので、調べてから待ち受けるまでの間にほかのプロセスに取られることがない

## 影響

- `terminal.spec.ts` の、同じポートで起動したときの E2E を変え、10 個すべて使われているときの E2E を足した
- `launch.spec.ts` に、`--port` の誤った値（`abc`・`70000`・`1.5`・`-1`）、`--port --fresh`、`--fresh=x` の E2E と、`--` のあとの `--help --version` がコマンドに渡る E2E を足し、`--help` の E2E で `--port` の説明を確かめるようにした
- README の使い方と、Live Share でポートを入力するところを「表示された URL のポート」にした
- npm の起動役と Homebrew の `test do` は変えない（起動役は引数と終了コードをそのまま渡す。`test do` は `free_port` の空いているポートで起動する）

## 含めないもの

- 上げない指定（`--strict-port` など）
- loopback 以外のアドレスや IPv6 で、ほかのプロセスが同じポートを使っているかどうかの扱い（OS によって、`127.0.0.1` で待ち受けられることがある。これまでと同じ）
