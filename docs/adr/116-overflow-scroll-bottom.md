# はみ出したターミナルを表示し直したとき、枠のスクロールを一番下にする

- 日付: 2026-10-22
- ストーリー: #116

## 背景

端末の大きさは、参加者のうち一番小さい表示領域に合わせ、下限（ウィンドウの大きさ）まで広げる（docs/adr/99-smallest-size.md）。下限より画面の小さい参加者は、はみ出した部分をペインの枠（`.pane-terminal`）のスクロールで見る。

Workspace を切り替えると、表示するターミナルの `Pane` を作り直す。ページを開き直したときも同じく作り直す。作り直した枠のスクロールは一番上（`scrollTop = 0`）から始まるので、最新の行（端末の下のほう）が見えず、毎回スクロールし直す必要があった。xterm の中のスクロール（スクロールバック）ではなく、枠のスクロールの話なので、`terminal.scrollToBottom()` では直らない。

## 決定

- `Pane` に「枠のスクロールを一番下に保つか」を持たせる。作ったときは保つ
- 最初の出力（つないだときに届く現在の画面）を書き終えたとき、枠と xterm の要素の大きさが変わったとき（サーバーが端末の大きさを決めた、フォントの大きさが変わった、表示領域が変わった）に、保つなら枠を一番下までスクロールする。大きさは出力の前後どちらで決まるか分からないので、両方で行う
- 枠がスクロールされたら、一番下にあるかで「保つか」を更新する。自分で上にスクロールしたら保たず、一番下に戻したらまた保つ

## 理由

- 表示し直したときに最新の行を見せたい、という要望に合う。表示し直す前に上へスクロールしていても、作り直した枠は一番下から見せる
- 大きさが決まるのは、最初の出力の前のことも後のこともある。書き終えたときだけ、大きさが変わったときだけのどちらかでは、順序によって一番下にならない
- 自分で上にスクロールしている間は、端末の大きさが変わっても一番下に引き戻さない（読んでいる位置を奪わない）

## 影響

- 表示し直したときだけでなく、使っている途中に端末の大きさが変わったときも、一番下にいれば一番下に保つ

## 含めないもの

- 横のスクロール（左端から見せる、いまのまま）
- Workspace を切り替えても `Pane` を作り直さず、枠のスクロール位置をそのまま残すこと
