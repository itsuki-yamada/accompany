# ペアプロモード

- 日付: 2026-10-20
- ストーリー: #93

## 背景

#69 のフォロー（[69-follow.md](69-follow.md)）を使ってみると、使いにくかった。特に、相手が自分をフォローしているかが分からない。「フォロー」というより「ペアプロモード」として、モードに入っていることがひと目で分かる UX にしたい。あわせて、相手のスクロール位置にも追従したい。

迷ったのは、次の点。

1. 呼び方と、始め方・やめ方
2. 追従している側の見せ方
3. 追従されている側への知らせ方と、そのための状態の置き場所
4. スクロール位置の追従のしかたと、自分でスクロールしたときの扱い

## 検討した選択肢

1. 始め方
   - A. いままでどおり、ターミナルのバーに出ている相手の名前のボタンだけ
   - B. A に加えて、ツールバーに参加者の一覧を置き、そこからも始められるようにする
   - C. サイドメニューに参加者の一覧を置く
2. 追従している側の見せ方
   - A. いままでどおり、ツールバーの表示と画面の縁（2px）だけ
   - B. 画面の縁を太くし、ツールバー・サイドメニュー・ターミナルのバーに相手の色を薄く敷く
   - C. 画面全体（端末の中も）に相手の色を薄く重ねる
3. 追従されている側への知らせ方
   - A. 出さない（ADR 69 のまま）
   - B. サーバーで「誰が誰に追従しているか」を持ち、presence の参加者ごとに `following` を足して配る。追従されている側のツールバーに出す
4. スクロール位置
   - 位置の表し方: (a) バッファの先頭からの行（`viewportY`）、(b) 一番下から何行戻しているか（`baseY - viewportY`）
   - 配り方: (a) 全員がいつも配る、(b) 追従されているあいだだけ配る
   - 自分でスクロールしたとき: (a) ペアプロモードをやめる、(b) ペアプロモードのまま、スクロールの追従だけを止める、(c) 何もしない（次に相手が動いたら戻る）

## 決定

1 は B、2 は B、3 は B、4 は (b)・(b)・(b) を採る。

- 呼び方を「ペアプロモード」にする。ツールバーの右側に、ほかの参加者の名前を並べ（role は group、名前は「参加者」）、押すと「〇〇とペアプロ」を始める。ターミナルのバーの名前のボタンも同じく「〇〇とペアプロ」にする。どちらも、もう一度押すとやめる
- ペアプロモードの間は、ツールバーに「ペアプロモード ／ 〇〇の画面に追従中 ／ やめる」を相手の色で出す。画面の縁を相手の色の 4px の outline で囲み、ツールバー・サイドメニュー・ターミナルのバーに相手の色を `color-mix` で薄く敷く。端末の中（文字と背景）には敷かない
- 追従されている側には、ツールバーに「〇〇があなたの画面に追従中」（複数なら「〇〇、△△が…」）を追従している人の色で出し、画面の縁をその色の 2px の outline で囲む（追従している側の 4px と見分けられるように細くする）
- ブラウザは、ペアプロモードを始めた・やめたときに `{ type: "follow", member }` を送る。サーバーは参加者ごとの `following` に持ち、presence で配る。自分といない参加者の番号や、番号でないもの（`null` など）は、やめたものとして扱う。追従されている人が抜けたら、その人に追従していた参加者の `following` を消す
- 追従されているあいだだけ、ブラウザはフォーカス先のターミナルのスクロール位置を `{ type: "scroll", terminal, offset }` で送る（スクロールは続けて起きるので 50ms ごとにまとめる）。`offset` は一番下から何行戻しているか。サーバーは、0 以上の整数で、あるターミナルのものだけを受け付け、presence の `scroll` に持って配る。追従され始めたときと、フォーカスを移したときにも送る
- 追従している側は、presence が届くたびと配置を組み立てたときに、相手の `scroll` が相手のフォーカス先のものなら、同じターミナルを同じ `offset` までスクロールする
- 追従している相手のターミナルを自分でスクロール（ホイール・スクロールバー）したら、ペアプロモードのまま、スクロールの追従だけを止める。ツールバーに「スクロールは追従していません」と「相手のスクロール位置に戻る」のボタンを出す。ボタンを押すか、相手が別のターミナルに移ると、また追従する
- フォーカスの追従と、やめる操作（相手と別のターミナルのクリック・右クリック・バーのボタン、隣のターミナルへ移るショートカット、通知のクリック、相手が抜けた）は、ADR 69 のまま

## 理由

- 1: ターミナルのバーの名前は、相手がいまいるターミナルにしか出ず、まだどこにもフォーカスしていない人や、別の Workspace にいる人は選べない。ツールバーはサイドメニューを隠していても常に見えるので、Live Share や Figma の参加者のアバターのように、始める場所として見つけやすい。サイドメニューはセッションの一覧が主で、隠している人もいる
- 2: 「モードに入っている」ことは、画面の端のほうの小さな表示より、画面全体の色が変わるほうが分かる。端末の中まで色を重ねると、配色の設定（#36）で選んだ背景と文字のコントラストが変わり読みにくくなるので、端末の外（縁とバー）だけを染める。縁は outline で中に重ねて描き、配置の大きさ（端末の大きさの計算）を変えない
- 3: 追従されている側が「見られている」と分からないことが、使いにくさの一番の理由だった。ADR 69 では、フォローは見る側の都合なのでサーバーに状態を持たない（1・2 の A）としたが、その「今後の課題」に挙げたとおり、presence に追従している相手を足す。追従そのもの（フォーカスとスクロールを動かすこと）は、これまでどおり追従している側のブラウザで行い、サーバーは知らせるためだけに持つ
- 4 の位置の表し方: 途中から参加した人や、サーバーの画面から復元した人は、スクロールバックの行数がほかの人と違うことがある。一番下からの行数なら、そのずれに影響されず、一番下（0）にいる人に追従すれば、新しい出力でも一番下に付いていく
- 4 の配り方: スクロールのたびに全員へ presence を配ると、サイドメニューや参加者の表示を何度も組み直す。追従されている人だけが送れば、ふだんの通信は変わらない
- 4 の自分でスクロールしたとき: スクロールは「ちょっと上を見たい」ときの操作で、そのたびにペアプロモードが切れると、また始め直す手間がかかる。止めずにそのまま追従すると、相手が少し動くたびに自分の見ている位置が飛ぶ。そこで、モードは保ったまま、スクロールの追従だけを止め、止めていることと戻し方をツールバーに出す
- 自分のスクロールかどうかは、xterm が原因を教えないので、直前（500ms 以内）にホイールかスクロールバーを操作したかで見分ける。相手の位置に合わせてスクロールするときは、直前の操作を忘れてから動かし、取り違えないようにする

## 影響・今後の課題

- presence の参加者に `following` と `scroll` が増える。#94（選択範囲の共有）も presence を触るので、合わせるときは両方を残す
- ADR 69 の「フォローされている側には専用の表示がない」「スクロール位置は追従しない」は、この ADR で置き換える。フォーカスの追従のしかたと、やめる操作は ADR 69 のまま
- 追従している相手が、まだどのターミナルにもフォーカスしていなければ、フォーカスもスクロールも動かない。ツールバーから始められるので、相手がフォーカスした時点で追従する
- 相手の位置に合わせた直後にそのターミナルへ画面の復元（タブの切り替えで接続し直したときなど）が届くと、スクロールバックが足りずに一番下に寄ることがある。相手が次にスクロールすれば合う
- 端末が自分の枠より大きいときの、枠の中の縦横のスクロール（#5・#51）は追従しない。端末の行のスクロールだけを追従する
- キーボード（Shift+PageUp など）や、自分の入力で一番下に戻ったときのスクロールは、自分でスクロールしたものとはみなさない

## 含めないもの

- 選択範囲の共有（#94 で、ペアプロモードでなくても見えるようにする）
- 拡大表示（#68）の追従
- 追従されている側から、追従をやめさせる操作
